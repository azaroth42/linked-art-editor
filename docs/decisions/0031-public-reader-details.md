# ADR-0031: Public Reader details

**Status:** Accepted · **Date:** 2026-11-22 · **Decided by:** Claude Opus 5.5 (Phase 1 Step 1.21; conventions §8.2 for the details the guide and spec §6.6, §12 leave open) · **Recorded by:** Claude

## Context
Step 1.21 replaces the minimal HTML of `GET /id/{uuid}` with the server-rendered Public Reader (decision D8): Jinja2, no React, labels through `hydrate_labels`, dates through `babel`, Canvas Panel for IIIF (decision D4, Spike S5 conditions), an Edit link for a session, a version banner, and no SPA code. The guide does not say where the reader's strings and script come from, which language the page is in when the caller prefers one the UI is not translated into, how to show BCE dates, which IIIF resources count, or how caching copes with a page that differs per session.

## Decision
1. **Strings.** The server reads the SPA's catalogue files, `frontend/public/locales/<lang>/reader.json` (namespace `reader`), as `lae.validation.diagnostics` already reads `errors.json`; there is no second copy. Messages use plain `{name}` arguments only, so `i18next-icu` and the server format them identically (a test enforces it). The template holds markup only; a test fails on any literal text in it. The product name in the page title, header and footer is "Laertes".
2. **Page language.** `<html lang>` is the first range of the locale chain (`lae.api.deps.locale_chain`) that has a reader catalogue, by RFC 4647 lookup, else `en`; `dir` comes from CLDR. The chain still chooses the record's labels, and every value whose language is known is marked with its own `lang` (a `Name`'s or statement's `language`, or the language of a label transcluded by `hydrate_labels`, which can now report it) and `dir="auto"`. A French reader therefore gets `lang="en"` chrome with `lang="fr"` titles while only English strings exist. Dates and numbers follow the page language.
3. **Dates.** A `TimeSpan` shows its display `Name` if it has one, with the period of its bounds after it when that differs; otherwise the period. The period has the coarsest precision the outer bounds allow (year, month, day; no times). An end at midnight is exclusive when it falls on the first of a month or the day after the start, else it is that day: published data uses both. Years before 1 (astronomical, `0000` = 1 BCE) are formatted through a stand-in year in the same place of the 400-year Gregorian cycle, with year and era taken from the real year; when either end is outside 1–9999 both ends carry the locale's era (`480 BC – 470 BC`).
4. **IIIF.** Canvas Panel is shown for the first IIIF resource of `representation` → `digitally_shown_by` (an image `DigitalObject` whose access point is a IIIF Image API URL or `info.json`, or that, or a `DigitalService` it is `digitally_available_via`, conforms to the Image API; or a `DigitalObject` conforming to the Presentation API), and then of `subject_of` → `digitally_carried_by` (a Manifest, where Linked Art and the Yale and Getty records put them). The server renders `<canvas-panel>` with kebab-case attributes, string booleans, `height`, `tabindex="0"`, `role="application"`, a label and keyboard help, plus `manifest-id` or `data-image-service`, and `data-region` from an Image API URL's region (pixels rounded and clamped to non-negative integers, or `pct:`). Canvas Panel shows nothing without a Canvas, so the script picks the Manifest's first Canvas through the shared IIIF vault, or builds a one-Canvas Manifest from the image service's `info.json` and loads it into the vault (synthetic ids are paths below the service, without a fragment). After `world-ready` it hides the fallback image and applies the region, clamped to the Canvas, with `setContentStateFromText`. Only `http(s)` URLs are used. Without JavaScript the page shows the record's first image (from an image service, at most 800×800 pixels) or a link to the Manifest. A/V has no transport controls until Step 2.12 (acknowledged for Step 0.10).
5. **Script.** `frontend/src/reader/main.ts` is a separate Vite build (`vite.reader.config.ts`, `corepack pnpm build:reader`, part of `pnpm build`) into `frontend/dist-reader/`: a 4.9 kB `reader.js` under a fixed name and the Canvas Panel chunk (587 kB, 173 kB gzip) under a hashed one, imported only when the page has a `<canvas-panel>`. `lae api` serves the directory at `/reader/assets/` (`LAE_READER_ASSETS_DIR` overrides it; 404 until built), so the page works wherever `/id/` is served. The `<script type="module">` is only on pages with a IIIF resource; other pages load no script and no stylesheet (the CSS is inline).
6. **Edit link and caching.** The link to `/edit/{uuid}` appears when the signed session cookie names a user (no database lookup). The HTML `ETag` is `W/"<record etag>-html-<fingerprint>[-edit]"`, where the fingerprint hashes the reader's code, template and catalogues, so a deployment that changes the page, or signing in, invalidates cached copies; the session middleware adds `Cookie` to `Vary` because the page reads the session. JSON-LD and Turtle tags are unchanged.

## Consequences
- Translating the reader is adding `frontend/public/locales/<lang>/reader.json`; the page switches to it for callers who prefer it, with English for missing keys. A deployment must ship `frontend/public/locales` with the backend (as for `errors.json`) and build `dist-reader` for the viewer.
- Measured locally (Step 1.21): first contentful paint without JavaScript 96–128 ms in the Playwright test; Lighthouse 13.6 on the same page, performance 1.0, accessibility 1.0, FCP 0.17 s (desktop preset) and 0.6 s (default mobile throttling).
- The midnight rule and the precision rule are display heuristics; the JSON-LD and Turtle links give the exact bounds.
- Canvas Panel's keyboard zoom steps from its own zoom level, not from a region set by a Content State, so `=` after a region view can zoom out; `0` resets. Recorded, not worked around.
- `?lang=` (spec §6.6), Memento, the citation widget, the Mermaid toggle and ephemeral translations are later work.
