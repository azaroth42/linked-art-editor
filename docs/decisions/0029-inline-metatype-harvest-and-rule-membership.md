# ADR-0029: Inline metatypes are harvested into `entity_labels`; rule membership joins them with QLever

**Status:** Accepted · **Date:** 2026-11-22 · **Decided by:** Claude Opus 5.5 as implementer of Phase 2 Step 2.1, on the orchestrator's instruction (Rob Sanderson may override) · **Recorded by:** Claude

## Context
Rule-backed Value Sets (spec §7.1) select concepts by Linked Art metatype ("concepts classified as AAT *Nationality*"), by `broader+` hierarchy roots, and by concept class. Step 2.1 resolves them in QLever over the default graph and the `urn:graph:sidecar:*` graphs.

ADR-0021 makes a concept reference inside a record (`{"id": aat:300111175, "type": "Type", "classified_as": [nationality]}`) emit only the link `<record> crm:P2_has_type <aat:300111175>`: the concept owns its description, including its metatype. So `<aat:300111175> crm:P2_has_type <nationality>` is in QLever only if the concept's own record or a sidecar graph says so, and the Phase 1 AAT stand-in (`lae bootstrap aat-labels`) carries labels only. The golden corpus has 183 such references (`docs/questions.md`, Step 1.3); LUX-style data states metatypes almost only this way. A QLever-only rule would leave rule Value Sets nearly empty, and the Step 2.2 rule that lets a binding "claim" a value by its metatype would never fire (`docs/questions.md`, Step 1.3, item 2). LUX solves the same problem by collecting the metatypes it sees on references (`reference_manager.walk_for_refs`) and adding them to the concept records it builds.

## Decision
1. **Harvest.** Every object of a published record, the root included, whose `type` is a concept class (`Type`, `Language`, `Material`, `MeasurementUnit`, `Currency`) and whose `id` is a string, contributes each string `id` of its `classified_as` as a metatype of that `id` (`lae.vocab.metatypes`). For a concept record's root that is its own metatype. `classified_as` on a `Person`, `Group`, `Place` or object reference is a classification and is not harvested.
2. **Where it goes.** The metatypes are added to `entity_labels.metatype_uris` of the concept's existing row. The harvest only adds (a union): it never removes a metatype because a record stopped repeating it, and it never creates a row (a concept without a row is an unresolved reference, ADR-0006; inventing a row would make it look resolved). It changes no other column, so `updated_at` and the autocomplete overlay are unaffected.
3. **When.** At publish, `lae.labels.upsert.upsert_entity_labels_for_record` (called in the publish transaction, Step 1.10) runs it for the published record. In bulk, one SQL statement over every active record (`jsonb_path_query` with the same selection, checked against the Python walk over the corpus) runs at the end of `lae bootstrap load` and of `lae bootstrap aat-labels`, and on demand as `lae vocab harvest-metatypes`, so a concept whose row is created after the records that type it (a sidecar loaded later) still gets its metatypes.
4. **Rule membership** (`lae.vocab.membership.refresh_membership`) is the union of: QLever (concepts whose `crm:P2_has_type` is a rule metatype, or that reach a root through `(skos:broader|crm:P127_has_broader_term)+`, with `rdf:type` one of the rule's `classes`, or of every concept class when `classes` is empty; with neither metatypes nor roots, every concept of `classes`); published `entity_labels` rows whose `metatype_uris` meet the rule's metatypes and whose `type` is in those classes (or, with neither metatypes nor roots, every row of those classes); and the Value Set's pinned terms. `exclusions` then removes the listed concepts themselves (not what is narrower). The result replaces `vocabulary_membership` for the set, and one `UPDATE … FROM` sets `entity_labels.vocab_ids`. Without QLever only the second and third parts apply.

## Alternatives considered
- **Write the harvested metatypes into the sidecar graphs in QLever.** QLever would then answer the whole rule, but a record's publish would have to write triples whose subject the record does not own, which is what ADR-0021 and decision A12 exclude; the Step 2.2 claim check reads `entity_labels` anyway.
- **A provenance table (concept, metatype, record) so that removals are exact.** Correct when a record drops an inline metatype, at the cost of a table maintained on every publish and bulk load. Metatypes of a concept are stable, and the concept, not the referencing record, is the authority; a stale inline assertion can be corrected on the concept. Not worth it now; can be added later without changing the column.
- **Create `entity_labels` rows for unknown concepts from the reference (`_label`, `type`).** Would change what "known" means for write-time stub normalization and the unresolved-reference finding (ADR-0006, decision A11).
- **Exclusions remove whole subtrees.** More useful for hierarchies, but the schema says "concepts removed from membership"; a subtree exclusion can be added as a new rule key later.

## Consequences
- Rule Value Sets work with the data institutions have, including when only references carry metatypes, and Step 2.2's claim rule sees the same metatypes the membership used.
- A metatype once harvested stays until the concept's row is rewritten by its owner. The Phase 2 sidecar manager (Step 2.14) must set a sidecar concept's own metatypes when it upserts its row, keep the harvested ones (union, or run `lae vocab harvest-metatypes` after the load), and then refresh rule memberships, as its guide text already says.
- `lae bootstrap load` and `aat-labels` each end with one pass over `records.data`; at the Step 2.20 volume it is a sequential scan with a JSON path per row and should be measured there.
- Membership is a snapshot: a concept published after a refresh joins its rule sets at the next refresh (Step 2.4's `POST /api/vocab/{id}/refresh`, `lae vocab refresh-membership`, the sidecar load); the Step 2.2 claim rule reads `metatype_uris` directly and is not delayed.

Evidence: `backend/tests/vocab/test_metatypes.py` (Python and SQL selection identical over every corpus record: 171 concept–metatype pairs in 112 records, for 54 concepts; union only; existing rows only; publish path), `backend/tests/vocab/test_membership.py` and `backend/tests/vocab/test_qlever.py` (a real QLever 0.6.0 index: a nationality typed only inline is a member, QLever alone does not have it; sidecar metatypes, `broader+` through both properties, class filter, exclusions).
