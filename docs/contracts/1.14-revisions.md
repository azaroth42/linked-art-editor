## 2. Interfaces

### 2.1 `lae.diff.semantic`

```python
def semantic_diff(old: dict[str, Any], new: dict[str, Any], *,
                  labels: Mapping[str, str] | None = None) -> list[Change]
def item_keys(items: list[Any]) -> list[str]
def format_path(parent: Sequence[Step], prop: str) -> str
def same_json(a: Any, b: Any) -> bool            # canonical_json equality
CHANGE_KINDS: tuple[str, ...]                    # the six kinds
```

`semantic_diff` is pure: no database, clock or randomness; inputs are not modified; `TypeError` if either argument is not a `dict`. Both arguments are projected JSON-LD of one record (internal node IRIs present). `labels` maps a URI to a display label; it affects only `label` fields and `path`.

Models (pydantic; `Change` is the union discriminated by `kind`):

```python
class Step:        property: str; key: str | None; id: str | None; type: str | None
                   classified_as: str | None; label: str | None
class RefSummary:  uri: str; type: str | None; label: str | None
class TextEdit:    index: int; delete: int; insert: str          # code points (R19)

# every change:    kind; path: str; parent: list[Step]; property: str
class AddNode:     key: str | None; before: str | None; node_type: str | None; node_id: str | None
                   summary_fields: dict[str, SummaryValue]; value: dict[str, Any]
class RemoveNode:  as AddNode without `before`
class AddRef:      key: str | None; before: str | None; uri: str; type: str | None
                   label: str | None; value: dict[str, Any]
class RemoveRef:   as AddRef without `before`
class UpdateLiteral: op: Literal["set", "change", "clear"]; key: str | None; before: str | None
                   old: Any; new: Any; text_edit: TextEdit | None
class Reorder:     order: list[str]; previous: list[str]
```

`SummaryValue = Scalar | RefSummary | list[Scalar | RefSummary]`, `Scalar = str | bool | int | float`. The guide's fields (`path`, `node_type`, `node_id`, `summary_fields`, `old`, `new`, `uri`, `type`) are all present with the guide's names; the others are additions needed for item 12 of §3. `old`, `new` and `value` are typed `Any` / `dict[str, Any]` so that no number is coerced. There is no model serializer: the OpenAPI schema of every model must list its fields (a wrap serializer collapses it to `additionalProperties`, measured).

### 2.2 Endpoints (`lae.api.revisions`, prefix `/api/records`)

| Route | Permission | Answer |
| :-- | :-- | :-- |
| `GET /{id}/revisions` (exists) | signed in | `[{version, created_at, authors, published_by, summary}]`, oldest first |
| `GET /{id}/revisions/{n}` (exists) | signed in | stored JSON-LD, node IRIs kept, labels transcluded |
| `GET /{id}/revisions/{m}/diff/{n}` | signed in | `SemanticDiff` from `m` to `n`; any order; `m = n` → no changes |
| `POST /{id}/draft/diff` | `edit_draft` (owner decision 2026-11-23; was `publish`) | `SemanticDiff` from the published version to the live draft |
| `POST /{id}/revisions/{n}/revert` | `publish` | `Reverted` |

```python
class SemanticDiff: record_id: UUID; from_version: int; to_version: int | None
                    draft_epoch: int | None; changes: list[Change]
class Reverted:     id: UUID; version: int; draft_epoch: int; base_version: int
```

The guide says the diff routes return "changes"; the envelope is the contract, because a bare array cannot gain fields. `to_version` is `None` and `draft_epoch` set for the draft diff; the reverse for a diff of two versions. Display labels follow the caller's `Accept-Language` (`locale_chain`), from one `entity_labels` query over the reference ids of both documents (`resolve_labels`), and the diff runs in `asyncio.to_thread`.

## 3. Invariants

**Vocabulary.** An *object* is the root, a node or a reference (R3). A property value has one of three *shapes*, decided from the JSON exactly as hydration decides (R8): *array* (a non-empty JSON array), *single* (a node or reference not in an array), *literal* (anything else: scalar, `Text` content, `[]`, opaque object, and `@context` whatever its form).

1. **Item keys are hydration's.** `item_keys(items)` returns, in array order, the R7 item key of each item: the `id` of a node or reference, `rules.value_key(item)` for an opaque item, made unique with `rules.unique_key` (` #2`, ` #3`, …). For any array of a projected document, `rules.entry_key(prop, key)` for these keys are exactly the map keys `hydrate` creates. (A node without `id`, which a projected document never has, is keyed by `value_key`.)
2. **Matching.** Roots are matched. Array items are matched by item key, so nodes by internal node IRI, references by target URI, and the *n*-th occurrence of a repeated `id` in `old` with the *n*-th in `new`. A single object is matched with the single object of the same property. Nothing is matched across properties or parents.
3. **Same object or replacement.** A matched pair is the same object only if both are nodes or references, their `id`s are equal and their `type`s are equal (`same_json`; both absent counts as equal); two objects without `id` only if `same_json`. The same object is compared property by property, whether it is a reference or a node (a reference that gains `classified_as` yields an `add_ref` inside it). Every other matched pair is a replacement: the old value removed whole and the new one added whole, same `key`. Consequently no change below the root ever has `property` `id` or `type`. Opaque items matched by key but not `same_json` are replacements too.
4. **Shape change.** If the shapes differ (including absent), every value on the old side is removed, in order, then every value on the new side added, in order, with `before = None`.
5. **Exact equality.** `1` ≠ `1.0` ≠ `true`; `-0.0` ≠ `0.0`; key order never matters; array order always does (R16). The list is empty exactly when `same_json(old, new)`.
6. **Kinds.** Adding or removing a reference (`is_reference`) is `add_ref` / `remove_ref`; any other node or reference (including an object with a foreign `id` and more than `id`, `type`, `_label`) is `add_node` / `remove_node`. A literal property is one `update_literal`: `op = "set"` when there was no value (`old` is `None` and meaningless), `"clear"` when there is none now, `"change"` when both exist (`None` is then JSON null). An opaque array item added or removed is `set` / `clear` with its `key`. `key` is the item key for an array item and `None` exactly when the property holds, or gets, a single value.
7. **Reorder.** At most one `reorder` per property per parent, emitted exactly when the keys present in both versions (not replacements) differ in relative order. `order` = every item key of `new`, in order; `previous` = the kept keys in `old`'s order. Additions and removals alone never produce one. A move inside an array is a `reorder`; a move to another property or parent is a `remove_node` plus an `add_node` with equal `node_id`.
8. **`before`.** On an addition to an array: the item key of the nearest following item of `new` that is kept, else `None` (append).
9. **Order of the list.** Depth-first from the root; properties of an object in code-point order of their keys; for one property: removals in `old`'s order, then the changes inside each kept object in `new`'s order, then additions in `new`'s order, then the `reorder`. The output does not depend on the key order of either input.
10. **Address.** `parent` is the chain of steps from the root to the object that has `property` (empty for the root): for each step the property, the item `key` (`None` for a single object), and `id`, `type`, first `classified_as` id and its label, all read from `new`. `path = format_path(parent, property)`: a step into an array item is `key[Type]`, `key[Type:Label]` when a label is known, `key[:Label]` when the type is not a string, bare `key` when neither; a step into a single object is the bare key; the last segment is the bare `property`. Example: `identified_by[Name:Primary Name].content`. Labels are not escaped; software uses `parent`, never `path`.
11. **Labels.** The label of an object is `labels[id]` if present, else its own `_label` if a string, else `None` (the precedence of `hydrate_labels`). `value`, `old` and `new` are always the input JSON, never with a looked-up label written in.
12. **Applying the list reproduces `new`.** For any two hydratable documents with every node identified: serializing the changes to JSON, parsing them back, and applying them in list order to `hydrate(old)` with the reference applier gives a document whose projection is `same_json` to `new`. The applier uses `lae.projection.ops` (`insert_item`, `remove_item`, `move_item`, `set_object`, `set_scalar`, `splice_text`, `remove_value`) and writes maps directly only for: a property key outside the path grammar or `id` / `type` **on the root**; a literal that is not a scalar; an added repeat (R7: operations never create one). It asserts that no change names `id` or `type` below the root, that every removed key exists, and that every added key is new. So the order of item 9 never asks an operation for something it rejects.
13. **Text edits.** For a `change` of `content` where `is_text_content` holds on both sides, `text_edit` is `rules.text_change(old, new)` (R23); it is `None` otherwise. `old` and `new` are still the whole strings. The applier applies the splice with `splice_text` and asserts the result equals `new`.
14. **`summary_fields`.** From the node's own properties, in key order, skipping `id`, `type`, `@context`: a string, number or boolean as is; a reference, or any node/reference whose `id` is not an internal node IRI of this record (`is_internal_node_iri(id, root id)`), as `RefSummary`; an array as the list of its items of those two sorts, omitted when that list is empty. Nested internal nodes, null and opaque objects are omitted.
15. **Versions resolve through `load_version` only** (ADR-0023 item 4). Facts on main since publish (PR #145, ADR-0033): a bulk-loaded record has its version-1 state only in `records.data` until its first publish, which back-fills a version-1 `record_revisions` row; a back-filled row has `published_by` NULL, `authors` empty, and may hold an empty N-Triples document (this step reads `jsonld_zstd` only and must never read `ntriples_zstd`); the outbox `from_version` is NULL on a first publish (not read here). A version with neither a row nor current `records.data` is 404 `LAE-REC-004` on the diff and the revert routes alike; the listing must not fail on a NULL `published_by`.
16. **Draft diff.** Old side = `records.data`; for `records.version = 0` the old side is `{k: data[k] for k in ("@context", "id", "type")}` and `from_version` is 0. New side = `CrdtWsClient.snapshot(id).jsonld`. The route never creates a draft.
17. **Revert discards only through the room manager and reports the new epoch.** In order: load the record (404), require `status = active` (409 `LAE-CRDT-005`), `load_version` (404), check `hydrate(revision.data, record.uri)` in a thread (422 `LAE-CRDT-008`); only then `crdt.close(id, discard=True)` followed by `crdt.open(id, content=revision.data, created_by=user.id)`. No `crdt_drafts` / `crdt_updates` row is deleted any other way (ADR-0027). The content is the stored JSON-LD unchanged, node IRIs included, so afterwards the snapshot is `same_json` to revision `n` and `draft/diff` equals `revisions/{current}/diff/{n}`.
18. **Revert race.** `open` answering 409 `LAE-CRDT-004` means another client created a draft between the two calls. The endpoint repeats discard + open, `REVERT_ATTEMPTS = 3` attempts in all, then passes the 409 on. Any other error is passed on at once.
19. **Revert publishes nothing.** `records.version`, `data`, `etag` and `record_revisions` are unchanged; `records.draft_epoch` is greater than the discarded draft's epoch and equals `Reverted.draft_epoch`; `base_version` = `records.version`. Failures before the discard leave the existing draft untouched.

## 4. Failure modes

| Situation | Caller sees | State afterwards |
| :-- | :-- | :-- |
| Anonymous / no `edit_draft` on `draft/diff`, no `publish` on revert | 401 / 403 | unchanged |
| Unknown record | 404 `LAE-REC-001` | unchanged |
| Version 0, beyond current, or a bulk-loaded version 1 that was never back-filled and is no longer current | 404 `LAE-REC-004` | unchanged (the draft is kept) |
| `draft/diff` without a draft | 404 `LAE-CRDT-003` | no draft created |
| *(§9.1)* `draft/diff`: the draft is based on another version than `records.version` in each of 3 reads | 409 `LAE-PUB-006` | unchanged |
| *(§9.2)* Revert names a `draft_epoch` the record has left | 409 `LAE-CRDT-007` | unchanged; `crdt-ws` not called |
| *(§9.2)* A publish commits between the revert's read and its `close` or `open`, and a draft has been opened since | 409 `LAE-CRDT-007` | the published version and that draft, untouched |
| Draft cannot be projected | 422 `LAE-CRDT-008` (from `snapshot`) | unchanged |
| Revert of a deleted or merged record | 409 `LAE-CRDT-005` | unchanged |
| `crdt-ws` down before the discard | 503 `LAE-CRDT-009` | unchanged |
| `crdt-ws` fails between discard and open | 503 / 502 | the old draft is gone, no new draft, epoch advanced; retrying the revert succeeds |
| Draft keeps reappearing | 409 `LAE-CRDT-004` | the other client's draft of the published version |
| Two reverts at once | both 200, or one 409 | the draft is one of the two revisions, whole |
| `semantic_diff` given a non-object | `TypeError` | — |

## 9. Amendment: the draft diff's 409, and a revert limited to the draft the caller meant (issue #178)

**By:** Claude Fable 5.2 (Phase 1 core review, Slice B) · **Date:** 2026-11-25

### 9.1 `draft/diff` answers 409 `LAE-PUB-006` (records #154 / PR #168; no code change)

Item 16 reads the `records` row and then the draft. A publish between the two reads paired version `N`'s data with a draft hydrated from version `N + 1` (or the reverse), and the diff reported the changes just published as still pending. PR #168 fixed it; this section is its contract.

16a. **The pair is used only when it is one state.** `_published_and_draft` reads the row (never from the session's identity map) and then the snapshot, and accepts the pair only if `snapshot.base_version == records.version`. Otherwise it reads both again, `DRAFT_DIFF_ATTEMPTS = 3` reads in all. After the third mismatch the answer is 409 `LAE-PUB-006` with `params = {id, base_version, version}` from the last read: the code, status and parameters publish gives the same draft (contract 1.10 §2.3). `SemanticDiff.from_version` is always the `records.version` of the accepted pair. The route still never creates a draft, and a record or draft that disappears between attempts is 404 `LAE-REC-001` / `LAE-CRDT-003` as on the first read.

Nothing changes a record under a live draft in Phase 1, so today only a publish landing between every one of three consecutive pairs of reads gets the 409; the editor's message for the code applies. A Phase 2 merge that rewrites a record under its draft will make it an ordinary answer.

Tests (`tests/api/test_revisions.py`, both on main since #168, verified against this text in the review):

25. `test_draft_diff_is_not_fooled_by_a_publish_between_its_reads`: a publish and a reconnect injected before the first snapshot; 200, `from_version` is the new version, no changes, exactly one re-read.
26. `test_draft_diff_gives_up_with_409_on_a_draft_of_another_version`: whole 409 body, and exactly `DRAFT_DIFF_ATTEMPTS` snapshots.

### 9.2 Revert discards only the draft the caller meant

**The defect.** Items 17 and 18 had revert call `crdt.close(id, discard=True)` without an epoch. A revert that arrived after the draft it was about had been published, or was overtaken by a publish between its read of the record and its discard, deleted the draft somebody had opened on the new version, and replaced it with the old revision. Confirmed by tests 27 and 28, which failed before the change. (The same defect and the same remedy for discard: contract 1.10 §8.)

**Interface.** `POST /{id}/revisions/{n}/revert` takes an optional body `{draft_epoch: int | null}` (`RevertRequest`): `records.draft_epoch` as the caller last saw it (`X-Draft-Epoch` of `GET /api/records/{id}`). No body, `{}` and null mean "the draft the record has when the request starts". A non-integer is 422. The History page always sends it.

**Error.** 409 `LAE-CRDT-007`, `params = {record_id}` (`lae.publish.service.draft_superseded`, shared with discard). No new code.

**Items 17 and 18, as amended.**

17. In order: load the record (404), require `status = active` (409 `LAE-CRDT-005`), and take `V = records.version`, `E = records.draft_epoch` from that read; if the body names an epoch other than `E` → 409 `LAE-CRDT-007`, before `crdt-ws` is called; `load_version` (404); the hydration check (422). Only then `crdt.close(id, discard=True, draft_epoch=E)` followed by `crdt.open(id, content=revision.data, created_by=user.id)`. Revert never calls `close` without an epoch. The rest of item 17 stands.
18. `open` answering 409 `LAE-CRDT-004` means a draft exists that this request did not discard. The endpoint reads the `records` row again (not from the identity map):
    - `records.version != V`: a publish overtook the request. The draft belongs to the new version and may hold edits → 409 `LAE-CRDT-007`, at once, on any attempt; that draft is not touched.
    - otherwise it is a draft of the same published version made since the discard (the reconnecting socket of the original item 18). On the last attempt the 409 `LAE-CRDT-004` is passed on; before that, `E` becomes the `records.draft_epoch` just read (that draft's epoch) and discard + open are repeated. `REVERT_ATTEMPTS = 3` attempts in all, as before.

    Any other error is passed on at once.

**What is not covered.** (a) A publish that overtakes the request with *no* draft opened afterwards: the conditional close finds nothing, `open` succeeds, and the draft holds revision `n` on top of the new version; `Reverted.base_version` names it (§8 item 4). Nothing is lost and nothing is published. (b) A draft discarded by someone else and started again, without a publish, inside the request's own window is indistinguishable from the reconnect of item 18 and is discarded for the retry, as it always was.

**§4, changed row.** "`crdt-ws` fails between discard and open": the epoch has advanced, so a retry that still names the old `draft_epoch` is 409 `LAE-CRDT-007`; a retry without one, or with the new one, succeeds. The History page reads the record again after any failed revert, so its next attempt names the current epoch.

Tests (`tests/api/test_revisions.py`):

27. `test_a_late_revert_leaves_the_draft_opened_after_a_publish`: publish, reopen, edit; a revert naming the published draft's epoch is 409 `LAE-CRDT-007` (whole body); record, revisions, events, draft and updates as before; with the current epoch the revert then succeeds.
28. `test_a_publish_during_the_revert_keeps_the_draft_opened_after_it`, with and without an epoch in the body: publish + reopen + edit injected just before the first `close` reaches `crdt-ws`; 409 `LAE-CRDT-007`; the new draft keeps its edit.
29. `test_a_revert_that_names_an_ended_epoch_discards_nothing`: 409 with no `close` sent; a non-integer epoch is 422.
30. `test_revert_retries_name_the_epoch_of_the_draft_that_came_back`: the three `close` calls of item 18 carry `E`, `E + 1`, `E + 2`.

Tests 23 (`…wins_against_a_client_that_reopens…`, `…gives_up_with_409…`) and the review's `test_revert_when_crdt_ws_fails_between_the_discard_and_the_open` are unchanged and still pass (none sends an epoch).

Mutations the reviewer ran (each must fail a test): `close` without `draft_epoch` (28, 30); no comparison of the body's epoch (27, 29); no version check before the retry (28); retry with the first epoch instead of the one read again (23, 30).

**Frontend (scaffolding).** `useCurrentRecord` returns `{jsonld, draftEpoch}` and is never served from the cache; `useRevert` takes `{version, draftEpoch}`, sends the body, and invalidates the record and the version list after a failure.
