## 2. Interfaces

### 2.1 Service (`lae.publish.service`)

```python
class AcceptedWarning(BaseModel):          # frozen
    code: str
    path: str                              # exact JSON Pointer
    record_id: UUID | None = None          # None = the record being published

class PublishResult(BaseModel):
    version: int                           # new records.version of the record asked for
    published: list[UUID]                  # that record first, then its stubs in UUID order
    draft_epoch: int                       # its new records.draft_epoch

class DiscardResult(BaseModel):
    id: UUID
    deleted: bool                          # the never-published record row is gone
    draft_epoch: int | None                # None when deleted

async def publish(record_id: UUID, user: CurrentUser, summary: str,
                  accepted_warnings: Collection[AcceptedWarning], *,
                  sessions: async_sessionmaker[AsyncSession],
                  crdt: CrdtWsClient, settings: Settings) -> PublishResult

async def discard(record_id: UUID, user: CurrentUser, *,
                  sessions: async_sessionmaker[AsyncSession],
                  crdt: CrdtWsClient) -> DiscardResult
```

*Amended for issue #178 (§8):* `discard` gains the keyword `draft_epoch: int | None = None`.

Both check `user.has("publish")` themselves (403 `LAE-AUTH-001`); callers in later phases do not come through HTTP. Both take the session factory, not a session: the service owns its transactions.

The guide writes `accepted_warnings: list[str]`; the endpoint body in the same step is `[{code, path}]`. The typed form above is the contract. `record_id` on a warning is an addition: paths are positions in one document, so a stub's warning must be accepted for that stub.

### 2.2 Endpoints (`lae.api.publish`, both require `publish`)

- `POST /api/records/{id}/publish`, body `{summary: str = "" (max 2000), accepted_warnings: [{code, path, record_id?}] = []}` → 200 `PublishResult`.
- `POST /api/records/{id}/draft/discard`, no body → 200 `DiscardResult`. *Amended for issue #178 (§8):* optional body `{draft_epoch: int | null}`; 409 `LAE-CRDT-007`.

The endpoint must release the request session's connection (`await session.rollback()` after authentication) before calling the service, so a request never holds one pooled connection while waiting for a second.

### 2.3 Error codes (`lae.publish.errors`; all `PublishError(ApiError)`; nothing has been written when one is raised)

| Code | Status | Meaning | `params` |
| :-- | :-- | :-- | :-- |
| `LAE-PUB-001` | 409 | The record, or a dependent stub, has no draft | `id` |
| `LAE-PUB-002` | 409 | Warnings not accepted | `records: {id: [warning diagnostics]}` (all current warnings), `unaccepted: [{record_id, code, path}]` |
| `LAE-PUB-003` | 422 | Violations | `records: {id: [all diagnostics of that record]}` for each record with a violation |
| `LAE-PUB-004` | 409 | A draft of the bundle changed, was published or was discarded after the validated snapshot | `id` (the first such record in lock order) |
| `LAE-PUB-005` | 409 | Record deleted or merged | `id`, `status` |
| `LAE-PUB-006` | 409 | `records.version` ≠ the snapshot's `base_version` | `id`, `base_version`, `version` |

Passed through unchanged: 404 `LAE-REC-001`; `CrdtWsError` from `snapshot` (503 `LAE-CRDT-009`, 422 `LAE-CRDT-008`). Each `LAE-PUB` code has an `errors.json` entry and a test keeps the two sets equal.

### 2.4 Outbox event (contract with Step 1.11)

One per published record: `kind='publish'`, `to_version` = new version, `from_version` = previous version, **NULL for a first publish** (`version` 0 → 1), `payload = {"context_version": <of to_version>, "drift_check": bool}`. When the event is visible, revisions for `to_version` and (if not NULL) `from_version` both exist. `drift_check = true` tells the worker to retract with `DELETE WHERE` over `owned_subjects` of `from_version`'s JSON-LD instead of a diff.

## 3. Invariants

Each is a property a named test in §5 checks.

**Sequence.** `publish` runs: (a) collect, (b) validate, (c) one write transaction, (d) close rooms. (a) and (b) use a read session that is closed before (c) begins.

1. **Bundle.** The bundle is the record plus, transitively, every record whose `uri` is referenced by a bundle member's snapshot and whose `records.version = 0`. Found by `records.uri = ANY(reference_ids)`, not by URI shape. Each member's snapshot comes from `CrdtWsClient.snapshot`; a member without a draft is `LAE-PUB-001` naming it. A referenced record at `version ≥ 1` is never bundled, whether or not it has a draft.
2. **Alias resolution first (ADR-0030).** In each snapshot, every reference whose `id` is a `record_aliases.alias_uri` is rewritten to that record's `uri` (`lae.aliases.resolve_aliases`, one query per document or one for the bundle; `lae.labels.refs.rewrite_references`). This happens before bundle discovery follows that document's references, before validation, and therefore before `normalize_refs`. The resolved document is the one validated and stored. The root `id` is never rewritten.
3. **Validation equals what is stored, apart from stripped `_label`s.** Each resolved snapshot goes through `load_reference_facts` + `validate_document` (the pipeline of `lae.validation.validate`) with `record_uri = records.uri` and `settings.context_version`. One deliberate difference from validating a draft alone: `ReferenceFacts.types` is overridden with `{member.uri: member snapshot's root type}` for every bundle member, because that is what `entity_labels` will say after the commit. Any violation in any member → `LAE-PUB-003`, checked before warnings.
4. **Warnings are an exact set match on `(record, code, path)`.** Every warning found must be in `accepted_warnings` (with `record_id` defaulting to the published record); no prefix, wildcard or code-only matching. Accepted entries that match nothing are ignored. `record_revisions.accepted_warnings` stores the warnings actually found for that record as `[{code, path}]`, deduplicated, ordered by `(path, code)`. `LAE-RDF-006` is acceptable like any other warning. `info` diagnostics are ignored.
5. **One transaction.** Everything in 6–13 is one PostgreSQL transaction at READ COMMITTED. Any exception rolls back; every table and both draft tables are then byte-for-byte as before.
6. **Lock order.** First every `records` row of the bundle `SELECT … FOR UPDATE`, one statement per row, in ascending UUID order (`sorted()` of `UUID`; the record asked for gets no precedence). Only then draft rows, in the same order. No draft row is touched before all record rows are held. A missing row → `LAE-PUB-004`; a non-active one → `LAE-PUB-005`.
7. **Nothing is published that was not validated.** For each member, `lae.crdt.store.draft_unchanged(session, id, snapshot.draft_epoch, snapshot.last_update_id)` must return `True` inside the transaction; `False` → `LAE-PUB-004`. No automatic retry. Then `records.version == snapshot.base_version` and `records.draft_epoch == snapshot.draft_epoch`, else `LAE-PUB-006`. All members pass these checks before the first write.
8. **Stored data.** `data = normalize_refs(resolved_snapshot, await known_reference_ids(session, resolved_snapshot) | {uri of every bundle member})`. Written to `records`: `data`, `type = data["type"]`, `version + 1`, `etag = record_etag(data)`, `context_version = settings.context_version`, `draft_epoch = snapshot.draft_epoch + 1`, `updated_at`.
9. **What is stored is what was expanded.** The new revision's `ntriples_zstd` is `compress(canonical_ntriples(expand_to_ntriples(data, context_version, record_uri=uri)))` and its `jsonld_zstd` is `compress(canonical_json(data))`, both from the exact `data` of item 8, computed in `asyncio.to_thread`. (So a version's snapshot hash equals the `records.etag` it had while current.) An `ExpansionError` here is answered as `LAE-PUB-003` with `expansion_diagnostic`, not a 500.
10. **Revision.** `authors = sorted(snapshot.contributors ∪ {user.id})`, `published_by = user.id`, `summary`, `accepted_warnings` per item 4, `context_version`.
11. **Bulk-loaded back-fill (decision A9; `docs/questions.md` Step 1.6).** If `version ≥ 1` before the publish and no `record_revisions` row exists for that version, insert one in the same transaction, before `records` is updated: JSON-LD and N-Triples of the current `records.data` under `records.context_version`, `authors = []`, `published_by = NULL`, `summary = ""`, `created_at = records.updated_at` as read under the lock. If that data cannot be expanded, the row stores an empty canonical N-Triples document. After any publish, every version from the back-filled one to `records.version` has a row.
12. **`drift_check` (ADR-0007, A13).** `False` except on a publish that back-filled. Then it is `False` only if the old data expanded, **and** `sync_state.bootstrap_context_version` equals both the record's previous `context_version` and `settings.context_version`, **and** `sync_state.bootstrap_expander_version == lae.rdf.EXPANDER_VERSION`. A missing key counts as a difference. (Key names: `lae.bootstrap.common`.)
13. **Per record, also in the transaction:**
    - `upsert_entity_labels_for_record(session, record)` after `records` is flushed (it runs the ADR-0032 metatype harvest; do not call the harvest a second way).
    - Every `qa_findings` row of the record with `status` `open` or `claimed` and `code LIKE 'LAE-SCHEMA-%'` is set to `resolved`, `resolved_by = user.id`, `updated_at = now()` (ADR-0030). Other codes are untouched.
    - The outbox event of §2.4.
    - `lae.crdt.store.delete_draft(session, id)`, after the `records` update is flushed, and never any other delete of `crdt_drafts` / `crdt_updates`. Its return value must equal `snapshot.draft_epoch + 1` (exactly one increment per publish); otherwise raise and roll back.
14. **After the commit**, for every member: `crdt.close(id, discard=True, draft_epoch=snapshot.draft_epoch)`. Failures are logged and swallowed; the publish result stands. Never call `close` without `draft_epoch` here.
15. **Double publish.** Two publishes that validated the same snapshot produce exactly one new version, one revision, one outbox event; the other gets `LAE-PUB-004` (or `LAE-PUB-001` if it started after the commit).
16. **Edits are never silently lost.** An update committed before the publish takes its record lock fails the publish (`LAE-PUB-004`) and stays in the draft. An update that arrives while the transaction holds its locks waits, then finds its draft gone (`DraftSupersededError`, socket 4409); it was never acknowledged and is not in the published version.
17. **Discard.** *Amended for issue #178: the close names an epoch; §8 replaces the first sentence.* `crdt.close(id, discard=True)` (no epoch: whatever draft there is). Then one transaction: lock the `records` row `FOR UPDATE`; if `version = 0` **and** a fresh statement finds no `crdt_drafts` row, delete the record row; otherwise leave it. The row lock is what keeps `crdt-ws` from inserting a draft between the check and the delete. No draft is not an error (200, `deleted: false`). If `crdt-ws` is unreachable nothing is deleted.

| Unaccepted warning in any member | 409 `LAE-PUB-002` | unchanged |

## 8. Amendment: a discard is limited to the draft the caller meant (issue #178)

**By:** Claude Fable 5.2 (Phase 1 core review, Slice B) · **Date:** 2026-11-25

**The defect.** Item 17 had `discard` call `crdt.close(id, discard=True)` without an epoch: "whatever draft there is". A discard request that reached the server after the draft it was about had been published (a slow network, a second tab, a publish by a colleague a moment earlier), or that was overtaken by a publish between its own read of the record and its call to `crdt-ws`, deleted the draft somebody had opened on the new version, with everything typed into it. For a record published for the first time in that window the answer was `deleted: false` with a new epoch, as if a draft had been discarded. Publish already limited its own close to the published draft's epoch (item 14); discard did not. Confirmed by tests 28 and 29, which failed before the change.

### 8.1 Interface

```python
async def discard(record_id: UUID, user: CurrentUser, *,
                  sessions: async_sessionmaker[AsyncSession],
                  crdt: CrdtWsClient,
                  draft_epoch: int | None = None) -> DiscardResult

def draft_superseded(record_id: UUID) -> ApiError      # 409 LAE-CRDT-007, params {record_id}
```

`POST /api/records/{id}/draft/discard` takes an optional body `{draft_epoch: int | null}` (`lae.api.publish.DiscardRequest`); no body, `{}` and `{"draft_epoch": null}` mean the same. A value that is not an integer is 422 (FastAPI). `draft_epoch` is the epoch the caller's editor is connected with (`X-Draft-Epoch` of `GET /api/records/{id}`, or the `draft_epoch` of the last publish, discard or revert answer). The editor always sends it. A caller that is not acting for a person looking at a draft (a later phase's batch job) may omit it.

**Error.** 409 `LAE-CRDT-007` (`lae.crdt.errors.DRAFT_SUPERSEDED`, "the draft was published or discarded in the meantime"), `params = {record_id}`. It is the code `crdt-ws` already answers for an update whose draft was published or discarded underneath it, and its message tells the user to reload; no new code. `LAE-PUB-004` was not used: its message is about a publish, and `PublishError` promises that nothing was written.

### 8.2 Invariants (item 17, replaced)

17. **Discard.** In order:
    1. Read `records.version` and `records.draft_epoch` (`V`, `E`); no row → 404 `LAE-REC-001`. A live draft always has its record's epoch (`lae.crdt.store`), so `E` names the record's draft if it has one.
    2. If the caller gave `draft_epoch` and it differs from `E` → 409 `LAE-CRDT-007`. Nothing is called and nothing changes.
    3. `crdt.close(id, discard=True, draft_epoch=E)`. Never without the epoch. A draft of another epoch (opened after a publish or another discard that got in between) is left with its room and sockets.
    4. One transaction, as before: lock the `records` row `FOR UPDATE`; if `version = 0` **and** a fresh statement finds no `crdt_drafts` row, delete the record row; otherwise leave it.
    5. If the record was not deleted, read `records.version` again. If it is no longer `V`, a publish overtook step 3: the draft became a version instead of being discarded → 409 `LAE-CRDT-007`. Otherwise 200 with the `records.draft_epoch` read in the same statement.

    No draft is not an error (200, `deleted: false`), unless the caller named an epoch the record has left (step 2). If `crdt-ws` is unreachable nothing is deleted.

    **What is not covered.** A draft discarded by someone else and opened again *between steps 1 and 3* has epoch `E + 1` and survives step 3; the answer is then 200 with `draft_epoch = E + 1` although a draft exists, exactly as when a socket reconnects right after the discard (test 27, "a record whose draft was reopened between close and delete is kept"). The client reconnects with the epoch of the answer and sees that draft. Nothing is lost in either case.

### 8.3 Failure modes (added to §4)

| Situation | Caller sees | State afterwards |
| :-- | :-- | :-- |
| `draft_epoch` given and the record is at another epoch (the draft was published or discarded before the request arrived) | 409 `LAE-CRDT-007` | unchanged; the current draft, its room and its sockets untouched |
| A publish commits between the discard's read and its `close` | 409 `LAE-CRDT-007` | the published version; a draft opened since is kept; a record published for the first time is not deleted |
| `draft_epoch` is not an integer | 422 (FastAPI) | unchanged |

## 9. Amendment: a deadlock in the write transaction is retried (issue #178)

**By:** Claude Fable 5.2 (Phase 1 core review, Slice B) · **Date:** 2026-11-25

**The defect.** Item 6 orders the locks on `records` and draft rows, and §4 concluded "Deadlock: must not occur". The transaction also locks `entity_labels` rows (item 13): the row of every record it publishes, and then, in the ADR-0032 metatype harvest, the rows of concepts those records cite inline. Two publishes of *different* records are not serialized by item 6, so two concepts that cite each other with a metatype the other's row does not have yet, published at the same moment, each hold their own label row and wait for the other's. PostgreSQL aborts one (SQLSTATE 40P01) and that editor got a 500. Nothing was lost or half-written (item 5), and repeating the publish worked, but the same cycle is open against every other writer of several `entity_labels` rows (the relabel backfill of Step 1.19b, vocabulary sync), and those run for minutes. Confirmed by test 31, which failed before the change.

Ordering the `entity_labels` locks was rejected: publish does not own that table, and an order kept by publish alone removes only the publish-against-publish case.

18. **Deadlock.** If the write transaction (items 5–13) fails with a `sqlalchemy.exc.DBAPIError` whose driver error has `sqlstate == "40P01"`, `publish` runs the write step again in a new session and transaction: `WRITE_ATTEMPTS = 3` transactions in all, then the error is passed on. Each attempt starts from the same validated bundle, takes the locks of item 6 and repeats the checks of item 7, so it writes exactly what a first attempt would have written or raises the same `LAE-PUB-004`/`-005`/`-006`. Nothing else is retried: no other SQLSTATE, no `PublishError`, and never the collect or validate phase (§6, "no automatic retry after `LAE-PUB-004`", stands). Each retry is logged (`publish_deadlock_retried`). Rooms are closed once, after the transaction that committed (item 14).

§4, the Deadlock row now reads: *on `records` and draft rows it must not occur (item 6); on any other row the publish is repeated (item 18) and the caller sees 200, or a 500 with nothing written after three aborted transactions.*
