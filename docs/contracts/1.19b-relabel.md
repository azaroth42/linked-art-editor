# Contract: Step 1.19b — Label language: admin relabel; AAT and vocabulary defaults follow the setting

**Step:** follow-up to Step 1.19a (issue #162; no guide step) · **Owner decisions:** 2026-11-23 (issue #162; `docs/questions.md`, "Owner's answers to items 5–9") · **Contract by:** Claude Fable 5.2 · **Date:** 2026-11-23

Read with: contract `1.19a-derived-label.md` (§2.1, §2.6, §3 items 3 and 14, §4) and ADR-0036; contract `1.10-publish.md` (§3 items 5, 6, 13); ADR-0030, ADR-0032; the module docstrings of `lae.labels.extract`, `lae.labels.upsert`, `lae.labels.transclude`, `lae.bootstrap.aat`, `lae.bootstrap.export`, `lae.vocab.service`, `lae.vocab.loader`, `lae.vocab.metatypes`, `lae.search.autocomplete`; `profiles/vocab/_schema.json` (`LangMap`).

**What the owner decided.** After `LAE_LABEL_LANGUAGE` is changed, an administrator can run a backfill that recomputes `entity_labels.default_label` under the new language. The AAT rows of `lae.bootstrap.aat` and the default label of a vocabulary term with a `label_override` follow the setting too. The setting stays an environment variable read at start, one language, no fallback list, and nothing checks at run time that the processes agree.

**What this contract decides.**

1. **The backfill is a CLI command, `lae relabel`, and nothing else.** Whoever changes the setting already edits the environment file and restarts the processes, so the administrator is the operator with a shell and the database credentials, as for `lae migrate`, `lae bootstrap` and `lae vocab import`. There is no HTTP route, so no signed-in user can start it. The work is a function (`lae.labels.relabel.relabel`) that Phase 2 Step 2.17 may later put behind `manage_system` and `admin_audit_log`; this step adds no endpoint, no job table and no permission.
2. **It writes one column: `entity_labels.default_label`.** It does not touch `records`, `record_revisions`, `outbox_events`, the draft tables, `qa_findings`, QLever or `crdt-ws`. **Published records keep the `_label` they were stored with** until each is next published, as 1.19a §4 already says. Reasons, which the implementer must not trade away:
   - Rewriting `records.data` without a revision breaks contract 1.10 §3 item 9 (a version's stored JSON-LD is what `records.etag` hashed). Rewriting it with a revision is a publish of every record by nobody: at 1M records that is 1M versions, 1M outbox events and SPARQL updates with no blue/green rebuild yet (Step 2.18), and every open draft would be refused with `LAE-PUB-006` because its base version moved. The owner's priority is that edit → validate → publish → sync stays solid.
   - Nothing a user sees depends on the stored `_label`: reference labels, autocomplete, the drafts list and the vocabulary bundle read `entity_labels`; the Public Reader title is computed at read time from the names under the setting (`lae.reader.view.record_title`). The stored `_label` shows only in raw JSON-LD and as `rdfs:label` in SPARQL.
3. **It never waits for a lock and never holds a `records` lock.** It locks `entity_labels` rows with `FOR UPDATE SKIP LOCKED`, reads the record afterwards, and retries skipped rows later. So it cannot deadlock with a publish and does not enter the publish lock order (1.10 §3 item 6).
4. **AAT and other non-record rows:** the label in the label language if the row has one, else the label in the source's own language (AAT: English), else the row is left alone (§2.2).
5. **A vocabulary term with a `label_override`:** the label in the label language from the term's merged labels, else the override's `en`, else the `entity_labels` default, else the URI (§2.4). The bundle's `ETag` covers the label language.

## 2. Interfaces

### 2.1 `lae.labels.defaults` (pure)

```python
SOURCE_LANGUAGES: Final[Mapping[str, str]] = {"aat": "en"}
"""entity_labels.source → the language that source's own preferred labels are written in."""

def default_label_from_labels(
    labels: Mapping[str, Any], label_language: str, source_language: str | None
) -> str | None
```

The default label of a row that has labels by language and no record to take names from. Only entries whose value is a string with a non-whitespace character count. In order:

1. the label in `label_language`: `lae.labels.transclude.match_label(usable, (label_language,))`, so the exact tag first, else the first tag in `sorted(key=str.lower)` order that starts with `label_language + "-"` (`fr` matches `fr`, then `fr-CA`);
2. else, if `source_language` is not `None`, the label in it, by the same matching;
3. else `None`: the caller keeps what it has.

It reuses `match_label` and does not reimplement it. `label_language` is a required positional parameter with no default (1.19a §2.1); the function reads no settings, never raises for any mapping and any strings, and does not modify its argument. `SOURCE_LANGUAGES` states a fact about a dataset, not a preference of the installation: it is the only place besides §2.4 where production code of this step names `en`, and it is consulted only after the label language found nothing (1.19a §3 item 14 holds).

### 2.2 The AAT seed (`lae.bootstrap.aat`)

`load_aat_labels` stores, per CSV row, `labels = {"en": preferred_name}` as today and `default_label = default_label_from_labels(labels, settings.label_language, SOURCE_LANGUAGES["aat"]) or preferred_name`. `AAT_LANGUAGE` is replaced by `SOURCE_LANGUAGES[AAT_SOURCE]`. The row is built by one function, `aat_row(term: AatTerm, label_language: str) -> tuple[str, str, str]` (`uri`, `labels` as JSON text, `default_label`), which the test calls. Everything else in the module is unchanged (upsert, report, metatype harvest, summary).

**Fallback order for AAT, stated once:** the AAT label in the label language; else the English preferred name. The Phase 1 CSV (`aat_code`, `preferred_name`, `description`) holds English names only, so **with this CSV every AAT default label is the English preferred name under every setting**; the rule takes effect for a row that has a label in the label language (Phase 2 Step 2.14's sidecar ingest, §6). The seed still overwrites `labels` on a re-run, as today.

### 2.3 `lae.labels.relabel`

```python
RELABEL_BATCH: Final = 500
RETRY_PASSES: Final = 5
RETRY_PAUSE_SECONDS: Final = 2.0

async def relabel(
    database_url: str,
    label_language: str,
    *,
    dry_run: bool = False,
    batch: int = RELABEL_BATCH,
    report_path: Path | None = None,
    retry_passes: int = RETRY_PASSES,
    retry_pause: float = RETRY_PAUSE_SECONDS,
) -> dict[str, Any]
```

One `asyncpg` connection (`lae.bootstrap.common.asyncpg_dsn`), raw SQL only: no ORM, because `EntityLabel.updated_at` has `onupdate` and the column must not move (§3 item 2). It needs PostgreSQL only: no QLever, no `crdt-ws`, no HTTP.

**What the new default label of a row is** (`e` an `entity_labels` row):

- `e.source == "local"` (`lae.labels.upsert.LOCAL_SOURCE`): `labels_from_record(r.data, label_language)[1]`, `r` being the `records` row with `r.uri = e.uri`, whatever its `status`, read whole (no projection of keys in SQL). That is exactly what publish writes (`upsert_entity_labels_for_record`). Without such a record the row is counted as `no_record` and left alone.
- any other source: `default_label_from_labels(e.labels, label_language, SOURCE_LANGUAGES.get(e.source))`; `None` means the row is left alone.

A row is written only when the new label is a different string from `e.default_label`.

**One batch**, as four module-level coroutines so that tests can park a run between them (the names are part of the contract):

1. `_page(conn, after: str, limit: int) -> list[str]`: `SELECT uri FROM entity_labels WHERE uri > $1 ORDER BY uri LIMIT $2`, no `COLLATE` clause (the primary key index serves it), starting from `""`. No transaction is open and no lock is taken.
2. Begin a transaction at READ COMMITTED. `_lock(conn, uris) -> list[Row]`: `SELECT uri, source, labels::text, default_label FROM entity_labels WHERE uri = ANY($1) FOR UPDATE SKIP LOCKED`. The uris it does not return are *deferred*.
3. `_records(conn, uris) -> dict[str, str]`: `SELECT uri, data::text FROM records WHERE uri = ANY($1)` for the locked local rows. **A statement of its own, sent after `_lock` has returned**: never joined into `_lock` or `_page`, and never read earlier (§3 item 4).
4. Compute in Python; `_apply(conn, changes)`: one `UPDATE entity_labels AS e SET default_label = v.label FROM unnest($1::text[], $2::text[]) AS v(uri, label) WHERE e.uri = v.uri`. Nothing else is in the `SET` list. Commit.

With `dry_run`, step 2 opens no transaction and runs the same `SELECT` without the locking clause, step 4 is skipped, and nothing is deferred.

**Deferred rows.** After the last page, up to `retry_passes` times while any remain: sleep `retry_pause` seconds, then run steps 2–4 over the deferred uris in batches. A uri still not obtained after the last pass is looked up with a plain `SELECT`: absent → `gone` (deleted meanwhile, not an error); present → `skipped_locked`.

**The registry touch.** When a run that is not a dry run reaches its end without an exception (whatever it changed or skipped), it runs, in a transaction of its own: `UPDATE vocabularies SET updated_at = clock_timestamp() WHERE id = (SELECT id FROM vocabularies ORDER BY id LIMIT 1)`. That moves `lae.vocab.service.registry_version`, so every `api` process rebuilds its bundle from the new default labels and every browser refetches it, without a restart. One row, one column; `version` and `updated_by` are not changed. With no Value Sets nothing is touched.

**Report.** With `report_path`, one JSON line per row changed (or, in a dry run, that would change): `{"uri", "source", "old", "new"}`, written as the batch commits.

**Summary** (the return value; the CLI prints it with `lae.bootstrap.common.print_summary`):

```json
{"command": "relabel", "label_language": "fr", "dry_run": false, "batch": 500,
 "rows": 0, "changed": {"local": 0, "aat": 0}, "changed_total": 0, "unchanged": 0,
 "no_record": 0, "kept": 0, "retried": 0, "skipped_locked": 0, "gone": 0,
 "registry_touched": true, "report": null, "seconds": 0.0}
```

`rows` is the number of uris paged. `kept` counts non-local rows for which `default_label_from_labels` gave `None`; `retried` counts rows obtained on a retry pass. Always `rows == changed_total + unchanged + no_record + kept + skipped_locked + gone`. `changed` has one key per source that had a change.

**Log** (`lae.logging.get_logger("lae.labels.relabel")`; until `admin_audit_log` exists this is the audit trail): `relabel_started` (`label_language`, `dry_run`, `batch`, `operator` = `getpass.getuser()` or `None`); `relabel_progress` after every tenth batch and every retry pass (`rows`, `changed_total`, `deferred`, `last_uri`); `relabel_finished` with the whole summary and `operator`; `relabel_failed` with the exception type before an exception is re-raised. No label text and no record data are logged.

### 2.4 The vocabulary bundle (`lae.vocab.service`)

`_resolved(term, row, label_language) -> tuple[dict[str, str], str]`. `labels` is the row's `labels` with the override laid over it tag by tag, as today. The default label:

- the term has no override (`None` or empty): `row.default_label`, else the URI, as today. That column already follows the setting (publish, bulk load, the AAT seed, `lae relabel`).
- the term has an override:
  1. `match_label(labels, (label_language,))` over the merged map: the label a reader of that language is served;
  2. else the override's `en` (the entry every `LangMap` must have, `profiles/vocab/_schema.json`: the curated label of last resort, not a second label language);
  3. else `row.default_label`;
  4. else the URI.

Under `en`, for every override that is a valid `LangMap`, the result is what it is today (the override's `en`).

A `label_override` keyed by language therefore works like this: each of its tags replaces the `entity_labels` label of the same tag in what the bundle serves as `label`; a reader gets the label of their own locale chain from that merged map (`resolve_label`, unchanged); the default label, shown when no locale matches, is chosen as above.

`label_language` is a required parameter, without a default, of `_resolved`, `build_bundle(session, version, label_language)`, `cached_bundle(session, label_language)`, `get_bundle(session, label_language)`, `search_terms(session, vocabulary_id, q, limit, chain, label_language)` and the two helpers it calls; `lae.api.vocab` passes `settings.label_language`.

**ETag and cache.** `bundle_etag(version, label_language)` hashes `f"{version}|{label_language}"` (same form, `W/"vocab-…"`). `registry_version` and `VocabBundle.version` are unchanged (Step 2.2 keys its rules on the registry alone). The in-process cache holds one bundle and is reused only when both the version and the label language are equal. So a browser that cached the bundle under one label language gets 200 and a new body from a process started with another; every ETag changes once when this step is deployed, which costs one refetch.

### 2.5 The command

`lae relabel [--dry-run] [--batch N] [--report PATH]`. `COMMANDS["relabel"] = "Recompute entity_labels.default_label under LAE_LABEL_LANGUAGE."` The handler reads `get_settings()`, configures logging, and runs `relabel(settings.database_url, settings.label_language, ...)`.

- **There is no language option.** The command relabels only under the value the installation is configured with.
- `--batch`: 1 to 10 000, default `RELABEL_BATCH`; anything else is an argparse error.
- Exit code 0 when `skipped_locked == 0`; 1 otherwise, with `lae relabel: N rows were locked by other transactions; run the command again` on stderr after the summary. An exception: the message on stderr, exit 1; batches already committed stay (§3 item 7).
- A bad `LAE_LABEL_LANGUAGE` stops the command when `Settings()` is built, before the database is opened (1.19a §2.6).

It is not a process: no Procfile entry, no systemd unit.

### 2.6 Changing the setting (`deploy/README.md`, replacing the comment's "nothing is migrated")

1. Set `LAE_LABEL_LANGUAGE` in the environment of every process.
2. Optional: `lae relabel --dry-run --report <file>` shows what would change; it writes nothing and may run at any time.
3. Restart `api` and `crdt-ws` together.
4. Run `lae relabel`, **after** the restart: a process still running with the old value would write old-language labels behind it. Expect exit code 0; on 1, run it again.
5. No second restart and no QLever rebuild. Not while `lae bootstrap load`, `lae bootstrap aat-labels` or a `lae vocab` command runs (their rows would be skipped as locked).

The README also says: the command may be repeated at any time and changes nothing the second time; published records keep their stored `_label` (and `rdfs:label` in QLever) until they are next published; switching back and running the command again restores the previous default labels.

### 2.7 Error codes

None new. The command reports through its exit code, summary and log.

## 3. Invariants

1. **A function of the stored data and the language.** After a run under `L` that skipped nothing, with no concurrent writer: every local row with a record has `default_label == labels_from_record(records.data, L)[1]`; every other row for which `default_label_from_labels(labels, L, SOURCE_LANGUAGES.get(source))` is not `None` has that value. The result does not depend on what `default_label` held before, except for rows left alone (`no_record`, `kept`).
2. **One column.** The only statement that writes `entity_labels` sets `default_label` and nothing else: `labels`, `type`, `primary_classification`, `metatype_uris`, `vocab_ids`, `usage_count`, `source`, `status` and **`updated_at`** are unchanged, also for changed rows. (`updated_at` feeds the autocomplete overlay, `lae.search.autocomplete.overlay_rows`: a relabel adds no literal that QLever's index lacks, and moving it for a large share of 1M rows would put them all in the overlay.) No row is inserted or deleted.
3. **Nothing else is written.** `records`, `record_revisions`, `outbox_events`, `crdt_drafts`, `crdt_updates`, `qa_findings`, `sync_state`, `record_aliases`, `vocabulary_terms`, `vocabulary_membership` and `slot_vocabulary_bindings` are byte for byte as before; of `vocabularies`, only the one `updated_at` of §2.3. No request reaches QLever or `crdt-ws`. The invariants of contracts 1.10, 1.11, 1.14 and 1.19a are untouched; publish, `lae.sync` and `lae.crdt` are not edited.
4. **Never behind a publish.** For a local row, the record is read by a statement that starts after the row's `entity_labels` lock is held. A publish of that record must take the same row lock for its upsert (1.10 §3 item 13), so either it committed before the lock, and the read sees its data, or it writes its own default label after the batch commits. After any interleaving of one relabel and any number of publishes, all run under `L`, the row equals `labels_from_record` of the committed `records.data` under `L`.
5. **Never waits, never blocks for long.** The relabel takes row locks only on `entity_labels`, only with `SKIP LOCKED`, and takes no lock on `records` or the draft tables. While it holds locks it runs only `_records` (a plain read) and `_apply` (rows it already holds), so it waits for no other transaction and can be in no deadlock cycle. Another transaction waits for it at most for one batch. Inside a batch transaction there is no sleep, no file read and no network call except to the database (report lines are written after the commit, or buffered).
6. **Idempotent.** A second run under the same `L` changes no row (`changed_total == 0`); it may touch the registry again.
7. **Crash-safe and resumable by repetition.** Each batch commits on its own. A run that stops midway leaves every row either relabelled or as it was, never anything else; running the command again completes the work. There is no resume state.
8. **Reversible.** After runs under `A`, then `B`, then `A`, every local row with a record and every non-local row that has a label in `A` or in its source language is as after the first run.
9. **Dry run writes nothing**: no table changes, the registry is not touched, no lock is taken; its `changed` counts and report lines equal those of a real run on the same data.
10. **Every row exactly once.** With no concurrent insert or delete, each `entity_labels` row is counted in exactly one of `changed`, `unchanged`, `no_record`, `kept`, `skipped_locked`, for every `batch ≥ 1`.
11. **The registry moves when a real run completes, and only then**: not in a dry run, not when the run raised.
12. **One language, no hidden default** (1.19a §3 item 14, extended). The AAT seed, the bundle, term search and `relabel` use `Settings.label_language`, handed down as an argument; none of them prefers `en` when the setting is `fr`. `en` appears only as AAT's source language and as the `LangMap` entry of last resort, each consulted after the label language.
13. **Under `en` nothing changes** for existing data: the AAT seed writes the rows it wrote before; the bundle built from `profiles/vocab/` has the same body (only its ETag differs); `lae relabel` on a database loaded and published under `en` changes no row.
14. **Seed and relabel agree.** Directly after `lae bootstrap aat-labels` under `L`, `relabel` under `L` changes no `aat` row.

## 4. Failure modes

| Situation | Result |
| :-- | :-- |
| A publish of a record is in flight and holds its `entity_labels` row | the row is deferred, retried after the pause; the publish's own label stands |
| A publish reaches its upsert while a batch holds the row | the publish waits for that batch (at most one), then writes its label; one version, one revision, one outbox event as always |
| A long transaction holds rows through every retry (`lae vocab refresh-usage`, a bulk load) | `skipped_locked > 0`, exit 1; run again |
| Run before the restart, or while one process still has the old value | rows published meanwhile carry the old language; nothing is lost; run again after the restart |
| The run is killed or the database goes away | committed batches stay, the registry is not touched, exit 1; run again |
| A local row without a `records` row | `no_record`, left alone |
| A non-local row with no label in the label language or its source language, or an unknown source without a label in the label language | `kept`, left alone |
| `labels` holds a blank or non-string value | that entry is ignored |
| A record without names | its default label is its `_label`, else its `id`, as at publish; usually unchanged |
| Published records after the run | `records.data`, the revisions and QLever keep the stored `_label`; the first `draft/diff` after the change may still show the one root `_label` change (1.19a §4); the Public Reader title, reference labels, autocomplete labels and the drafts list show the new language |
| A record published since the last QLever index build | the overlay finds it by its default label only, so after the change by the new-language name only, until the next index build; as for any record published after the change |
| No Value Sets | `registry_touched: false` |
| A browser holds a bundle cached under the other label language | its `If-None-Match` no longer matches: 200 with the new bundle |
| An override without `en` (not a valid `LangMap`, written past the schema) | steps 1, 3, 4 of §2.4; no exception |
| `--batch 0`, an unknown option, `--language` | argparse error, exit 2, nothing done |
| `LAE_LABEL_LANGUAGE` invalid | `ValidationError` before the database is opened |
