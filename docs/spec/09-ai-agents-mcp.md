## 9. AI Agent Collaboration (Model Context Protocol / MCP)

AI agents participate in the editor as first-class collaborative contributors and reviewers via an embedded **Model Context Protocol (MCP)** server, leveraging both live CRDT draft rooms (for single-record edits) and the `curation_proposals` queue (for cross-record merges) with tiered governance and human escalation.

* **Stateless Streamable HTTP Transport:** Mounted directly at `/mcp` inside the FastAPI service using the official MCP Python SDK v2 (stateless Streamable HTTP transport with explicit state handles and cacheable resource metadata, backwards-compatible with earlier MCP clients).  
* **Unified Auth, Attribution & Mandatory CRDT Routing:** Agents authenticate through the same OAuth 2.0 / OIDC and scoped service-account token layer across two role tiers (Tier 1 discovery/draft agents with `edit_draft` and `propose_merge`; Tier 2 frontier arbiter agents with `review_proposal` and guardrail-scoped `approve_merge_scoped`). Single-record draft mutations MUST route through the `pycrdt` room manager—never writing directly to PostgreSQL—so human editors viewing the same record see agent edits stream in live with a distinct "AI Agent" presence badge in Yjs Awareness. Committed revisions record agent service accounts (and model identifiers) in multi-author attribution and support Linked Art `AttributeAssignment` provenance for model-generated claims.  
* **Schema-Aware MCP Surface:** Exposes high-level semantic primitives so agents never hand-author fragile raw CIDOC-CRM JSON-LD:  
  * *Read-Only Resources:* `linkedart://record/{uuid}`, `linkedart://draft/{uuid}`, `linkedart://profile/{class}`, `linkedart://shapes/{class}`, `linkedart://vocabularies`, `linkedart://vocabulary/{id}`, `linkedart://proposals/pending?type=merge`, `linkedart://proposal/{id}`, and `linkedart://qa/worklists` (providing hydrated records, active diffs, UI Profiles, SHACL shapes, curated Value Sets, slot bindings, scope notes, bundled hydrated JSON-LD of both records, QLever backlink summaries, Tier 1 evidence, prior rejected merge history, and structured cross-record QA and link-rot findings).  
  * *Discovery & Reconciliation Tools:* `search_entities` (supporting hybrid lexical + semantic `pgvector` search), `run_sparql_readonly` (able to call FastAPI's `/sparql/vector` SPARQL `SERVICE` for multilingual concept discovery and duplicate-detection sweeps), `get_backlinks`, and `reconcile_entity` (invoking the on-demand reconciliation service).  
  * *Draft Authoring Tools:* `create_draft_record`, `set_preferred_name`, `add_statement`, `add_classification`, `set_production`, `add_equivalent`, `set_place_wkt`, and `add_comment` (automatically minting internal sub-node slash IRIs, normalizing stubs, and anchoring agent questions to specific nodes).  
  * *Validation & Long-Running Tasks:* `validate_draft` and `preview_semantic_diff` (enabling agent self-correction loops against JSON-Schema + SHACL until zero `sh:Violation` errors remain), `translate_record_fields` (running on a server-owned **asynchronous job model**—an `agent_jobs` table, `linkedart://job/{id}` progress resources, and `cancel_job`—rather than the MCP Tasks extension, which MCP Python SDK v2 does not implement—so Tier 1 agents can batch-translate a `Set` or exhibition checklist into live `pycrdt` draft rooms with `AttributeAssignment` provenance, subject to `edit_draft` permissions, Agent Operations Console quotas, and Editor-gated publication in the Active Drafts & Review Inbox), with the same job model covering other asynchronous multi-record workflows such as IIIF transcription or batch set enrichment.  
* **Embedded Agent Chat Orchestrator & Multi-Provider LLM Layer:** FastAPI hosts an in-process **Agent Chat Orchestrator** that connects as an MCP client directly to `/mcp`—eliminating duplicated tool definitions while guaranteeing mandatory `pycrdt` room routing, `agent_audit_log` recording, `agent_quotas` enforcement, and circuit-breaker compliance. Extends the OpenAI-compatible local LLM client into a unified **Multi-Provider LLM Adapter Layer** (thin native adapters or `litellm`) supporting local models (`llama.cpp` server, `vLLM`, `Ollama`) alongside cloud frontier providers (Google Gemini, Anthropic Claude, OpenAI, and institutional Vertex AI / AWS Bedrock / Azure OpenAI endpoints). API keys are configured primarily by institutional Admins in `llm_provider_configs` (envelope-encrypted at rest, never sent to browsers or logged), with optional admin-togglable **per-user BYOK** keys scoped strictly to that user's own sessions, governed by an instance-level `local_only` vs. `allow_cloud` policy switch.  
  * *Proposal & Two-Tier Merge Review Tools:* Tier 1 calls `propose_merge(source_uri, target_uri, evidence, field_resolution_plan)` (automatically deduplicating and rejecting blocked "Do Not Merge" pairs via the negative cache). Tier 2 calls `claim_proposal(proposal_id)` (short lease preventing duplicate parallel reviews), `approve_merge(proposal_id, rationale, final_field_plan)` (executes only if server-side blast-radius guardrails pass; otherwise automatically routes to human review), `reject_merge(proposal_id, rationale, block_future=True)` (populates negative cache), and `escalate_to_human(proposal_id, rationale)` (flags `needs_human_review` for the Visual Merge Workbench).  
* **Agent Observability, Quotas & Circuit Breaker (Agent Operations Console):** Dedicated Admin/Editor operations console tracking per-agent rate limits, daily auto-merge caps, live MCP tool-call audit logs (`agent_audit_log`), per-user and per-provider token and spend caps for cloud chat models, and **per-model over-merge / unmerge rate metrics**, paired with a 1-click **"Pause All Agents / Pause Auto-Merge"** circuit breaker to halt misbehaving models or prompt regressions immediately.
