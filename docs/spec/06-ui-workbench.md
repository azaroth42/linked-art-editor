## 6. Schema-Driven UI & Ergonomics

### 6.1 Declarative UI Profile Layer

SHACL and JSON-Schema define *what is valid*, not *how humans should edit it*. A separate declarative **UI Profile** (YAML/JSON per Linked Art class—`HumanMadeObject`, `Person`, `Group`, `Place`, `VisualItem`, `Set`, `Concept`) drives form rendering:

* **Path Flattening:** Maps deep CRM paths into single visual controls. Example: A single "Creation Date" widget reads and writes `produced_by.timespan.{begin_of_the_begin, end_of_the_end, identified_by[0].content}`.  
* **Progressive Disclosure:** Surfaces the 20% of properties used in 90% of cataloging by default; tucks specialized CRM paths (e.g., `part_of`, `changed_ownership_through`, `assigned_by`) behind "+ Add Details" panels.  
* **Lossless Round-Tripping:** The frontend maintains the full source JSON-LD AST in memory and applies targeted mutations only to nodes bound to active UI controls. Any unrecognized or unprofiled properties are preserved verbatim on save (with an optional "Raw JSON-LD Inspector" drawer for power users).  
* **Contextual Value Set Binding & Card Partitioning:** Profile slots bind to named Value Sets from the Vocabulary Management Layer so multi-purpose `classified_as` arrays automatically partition into distinct, class-appropriate UI cards (e.g., Gender, Occupation, and Nationality on `Person` vs. Type of Work, Style, and Shape on `HumanMadeObject`). Any valid `Type` in `classified_as` not matched by a configured Value Set surfaces in a lossless **"Other Classifications"** fallback bucket rather than being hidden or stripped on save.  
* **BCP-47 `LangMap` Config Localization:** All human-readable UI Profile strings (`sections[].label`, `slots[].label`, `help_text`, `grid_columns[].label`) are stored as BCP-47 language maps (`{ "en": "Type of Work" }`) resolved via a shared RFC 4647 fallback chain rather than bare strings.

### 6.2 Specialized Cultural Heritage Widgets

* **EDTF / Fuzzy Dates:** Parses Extended Date/Time Format strings (e.g., `1880~/1895?`) directly into Linked Art `TimeSpan` bounds and human-readable display labels.  
* **Multilingual Strings:** Native BCP-47 language selector, per-field script direction (`dir="rtl" | "ltr" | "auto"`, decoupled from UI chrome direction so an Arabic title renders RTL cleanly inside an English workbench), preferred-vs-alternate `Name` classification toggles, and a 1-click **"Translate to..."** inline action streaming local LLM output directly into an additive, provenance-tracked sibling node in the live CRDT room.  
* **IIIF Media Integration:** Inline **Canvas Panel** (Digirati's embeddable web component on IIIF Vault, React-compatible) as the editor's viewer: lightweight single-canvas embedding, native IIIF Content State and region selection for SpecificResource / Media Fragment detail references, annotation display, and manifest navigation via its companion `sequence-panel`. Time-based media (IIIF A/V) also uses Canvas Panel; Clover and Mirador are not used (ADR-0012).  
* **Map Authoring UI (Place.defined_by):** Interactive **MapLibre GL JS** + **Terra Draw** editor supporting **Points**, **Bounding Boxes** (drag-to-draw closed 5-vertex POLYGON), and **Polygons** / MULTIPOLYGONs (with vertex editing and inner holes). Automatically normalizes WGS84/CRS84 lon lat coordinate order and OGC counter-clockwise outer-ring winding before serializing to defined_by (geo:wktLiteral), supports raw WKT paste and .geojson file drop, and provides 1-click geometry seeding from locally loaded Linked Art gazetteer sidecar datasets (e.g., TGN, Wikidata, GeoNames, WHG). Geometries are stored as atomic LWW values in the Y.Map (avoiding concurrent vertex corruption) with active map-editing state broadcast via Yjs Awareness, and index directly into QLever's native GeoSPARQL spatial index.

### 6.3 Context-Aware Real-Time Autocomplete & Reconciliation

* **Local & Sidecar Search (QLever):** Prefix/full-text SPARQL queries across both local records and locally loaded Linked Art sidecar datasets (AAT, ULAN, TGN, Wikidata, etc.) ranked by local usage frequency, returning label, disambiguating context (lifespan dates, parent hierarchy), and URI in under 100ms—with zero live external web or remote SPARQL calls during CRDT editing.  
* **On-Demand Reconciliation Service Callout:** Explicitly invoked by an editor (or MCP agent)—never run automatically in the background due to compute cost—sending the record to a dedicated `lae-reconcile` process to review ranked candidate URIs and confirm `equivalent` links or initiate an entity merge. The LUX data pipeline has no reconciliation service to wrap: its reconciler is exact-key name and identifier lookup over LMDB indexes with a differents blocklist, embedded in a batch build. `lae-reconcile` therefore vendors that reconciler and index code, runs with network access disabled, and is extended to return ranked candidates with match evidence (which name variant or external identifier matched), paired with the editor's lexical and semantic candidate search for fuzzy suggestions.  
* **Inline Stub Creation:** If an entity does not exist locally or in sidecar datasets, users can click *"+ Create new Person/Place/Concept"* inside the autocomplete dropdown, fill a minimal modal, mint a draft stub immediately, and publish it atomically alongside the parent record via bundled transactional publish.  
* **Pre-Creation Duplicate Guard ("Did You Mean...?"):** Runs a lightweight live check combining QLever lexical search and `pgvector` semantic similarity directly inside both the *"Create New Record"* and *"Inline Stub Creation"* modals, warning catalogers about near-duplicate existing entities before a new UUIDv7 is minted.  
* **Hybrid Lexical + Semantic Autocomplete (pgvector + RRF):** For `rule`-backed Value Sets and open entity-reference slots targeting Concepts and Reference Authorities (skipping small client-side `enumerated` Value Sets already shipped in the boot bundle), the editor pairs fast QLever prefix/full-text search (<20ms per keystroke) with debounced (\~150–200ms) semantic vector search over PostgreSQL `entity_embeddings` (`pgvector halfvec` HNSW), natively filtered in SQL by `entity_labels.vocab_ids`, `metatype_uris`, and target class. Query strings are embedded in <20–40ms by a warm local multilingual embedding worker (ONNX Runtime / `llama.cpp` alongside FastAPI, with zero remote API calls). Results merge via **Reciprocal Rank Fusion (RRF)**, tagging purely conceptual hits with a subtle *"Semantic match"* badge so catalogers immediately see why a non-matching label surfaced (e.g., *"round painting"* -> *tondo*).  
* **QLever SPARQL SERVICE Integration (Two-Store Simplicity):** FastAPI exposes a lightweight `/sparql/vector` SPARQL `SERVICE` wrapper backed by PostgreSQL `pgvector` so QLever graph queries and Tier 1 MCP duplicate-detection sweeps can invoke semantic similarity natively inside SPARQL without deploying or syncing a third vector store. Abstracting vector search behind this single FastAPI/`SERVICE` contract also leaves a clean drop-in migration seam if QLever's native dense vector indexing matures later.

### 6.4 Ontology-Aware Drag-and-Drop Workbench

* **Typed Drag-and-Drop for Local Records:** A collapsible **Entity Workbench** surfaces search results, recently viewed records, and a persistent pinned tray (so catalogers can pin recurring entities such as an artist, place, or material and drag them across records). Uses native HTML5 Drag-and-Drop (or @dnd-kit with HTML5 fallback) carrying a custom MIME payload (application/x-linked-art-ref+json with id, type, _label, and primary classified_as) plus a text/uri-list fallback for cross-tab dragging. Nodes can also be dragged directly out of the **Force-Directed Graph Explorer** using the same `application/x-linked-art-ref+json` drag payload. Initiating a drag highlights schema-valid drop targets across the active record using UI Profile, SHACL range/classification rules, and Value Set / metatype constraints (e.g., dragging a `Person` highlights `produced_by.carried_out_by`, `current_owner`, and `about`, while dragging a Style concept like *Baroque* highlights the **Style** slot on a `HumanMadeObject` and dims **Occupation**, **Gender**, and **Type of Work**) and auto-expands collapsed progressive-disclosure sections after \~400ms of hover. Because entity-reference sets are target-URI-keyed Y.Maps, duplicate drops deduplicate idempotently.  
* **Drag-and-Drop for Images, IIIF Manifests & Web Pages:** Dropping external URLs or IIIF drag-and-drop badges/Content State payloads onto a slot or the record canvas routes through a lightweight FastAPI **Resource Introspection Proxy** (bypassing browser CORS limits) to detect the resource type and generate the appropriate Linked Art subgraph:  
  * *IIIF Manifest / Content State:* Maps to subject_of -> LinguisticObject / DigitalObject (conforms_to IIIF Presentation API, access_point) and loads immediately in the inline Canvas Panel viewer.  
  * *Direct Image URL / IIIF Image (info.json):* Maps to representation -> VisualItem -> digitally_shown_by -> DigitalObject (format, access_point, classified_as AAT digital images).  
  * *Generic Web Page (text/html):* Scrapes title, OpenGraph, or embedded JSON-LD into subject_of -> LinguisticObject (classified_as AAT web pages, identified_by title, digitally_carried_by -> DigitalObject with access_point).  
  * *External Linked Data URI:* Offers 1-click insertion into equivalent (or as a typed entity reference when dropped on a relational slot).  
* **Canvas vs. Slot Disambiguation & Asset Boundary:** Dropping directly onto a typed slot commits immediately to that property; dropping onto the record header or an ambiguous zone opens a 1-click disambiguation popover (e.g., "Add as Primary Representation" vs. "Add as Homepage / Reference (subject_of)"). v1 stays URL-based to keep the editor decoupled from digital asset storage, with an optional S3/IIIF upload extension point for desktop file drops.

### 6.5 Power-User Workbench & Productivity Affordances

* **Record Cloning & Starter Templates ("Create Similar"):** Clones an existing record—automatically minting a fresh UUIDv7 root URI and fresh internal sub-node slash IRIs while clearing unique identifiers/accession numbers—or instantiates saved class starter templates for repetitive cataloging (e.g., print series, archival boxes). Also supports **Linked-Entity Composite Creation Flows** (e.g., *"Create Object + VisualItem together"*, published atomically via the existing bundled transactional publish).  
* **Split-Screen / Dual-Pane Editing & Visual Merge Workbench:** Opens two records side-by-side for natural cross-record drag-and-drop, parallel transcription/description (e.g., `LinguisticObject` alongside its carrying `HumanMadeObject`), and field-by-field comparison prior to executing an entity merge. It also serves as the human review queue for `needs_human_review` proposals escalated by Tier 2 reviewer agents, displaying Tier 1 evidence, Tier 2 rationale, and 1-click Approve, Reject (with negative-cache blocking), or Unmerge actions. In addition, it powers the **Entity Split Workbench** (for separating conflated records and selectively reassigning inbound backlinks) and the **Safe Record Reclassification Wizard**.  
* **Interactive Backlinks ("What Links Here") & Neighborhood Mini-Graph:** QLever-powered inbound references panel grouped by predicate (e.g., *"42 objects produced by · 5 exhibitions"*) with quick unlink/reassign actions to resolve delete-protection blocks, inline **Inverse-Link Authoring ("Add Linked Record")** actions directly inside the Backlinks panel (opening/mutating the referencing record's CRDT draft rather than forcing manual tab-hopping), paired with an optional 1–2 hop visual graph drawer (React Flow) for inspecting `Set` hierarchies, `part_of` containment, and carrier/work chains.  
* **Chronological Timeline View:** Interactive chronological strip for nested provenance (`changed_ownership_through`) and `Activity` chains to visually audit date gaps, reversed `TimeSpan` bounds, and conflicting custody assertions.  
* **Grid / Spreadsheet View for Sets & Query Results:** Editable table view (TanStack Table) over a `Set` or QLever result list whose columns map directly to Declarative UI Profile paths, enabling fill-down, multi-row find-and-replace, and batch publishing.  
* **Keyboard-First Velocity, Scoped Undo & Smart Paste:** Global `Cmd+K` command palette for instant navigation across 10M+ records and actions; **user-scoped Undo/Redo** via Yjs `UndoManager` (reverting only the caller's edits in a shared CRDT room without clobbering co-editors); and **Smart Paste** routing pasted IIIF Manifest URLs, external URIs, web pages, or WKT strings through the FastAPI Resource Introspection Proxy.  
* **Curation Campaign & Queue Focus Mode:** Distraction-free sequential workflow (`Prev` / `Next` / `Skip` / `Mark Reviewed` with progress tracking and optional cataloger assignment, backed by `curation_campaigns`) over any `Set`, Dynamic Smart Set, or `qa_findings` worklist so catalogers or student assistants can work steadily through large remediation batches (e.g., 500 unlocated `Place`s or 200 machine-translated titles) without returning to a search grid after every record.

### 6.6 Graph Visualization, Record Diagramming, Macro-Explorers & Public Reader

* **Multi-Record Force-Directed Graph Explorer:** Dedicated WebGL/Canvas graph explorer (**Sigma.js + Graphology**, **Cosmograph**, or `react-force-graph-2d`) rendering 500–5,000 connected records at 60fps, color-coded by Linked Art core class with predicate-styled edges. Includes **supernode protection** (capping expansion per click—e.g., top 25 neighbors—collapsing high-degree hubs into expandable cluster badges such as *"+ 14,200 more HumanMadeObjects"*, and filtering expansion by predicate), **drag-to-form** linking, **cluster-to-merge** lasso selection opening the Visual Merge Workbench, a QLever **shortest 1–4 hop path finder**, and a **live CRDT draft overlay** (rendering published edges solid and unpublished additions/removals as dashed green/red edges).  
* **Single-Record Mermaid Diagramming:** Pure-function client-side Mermaid (`graph LR` / `flowchart TD`) generator projecting the live CRDT record's internal CIDOC-CRM structure reactively as humans or MCP agents edit, using clean local aliases so internal slash-path sub-node IRIs are never exposed. Offers three views: **Conceptual View** (hiding boilerplate `Name`/`Identifier` leaves), **Full Linked Art / CRM View** (including `classified_as` badges, literals, and `AttributeAssignment` chains), and **Visual Diff Mode** (`classDef` green/red/amber highlighting inside Pre-Publish Diff and Merge Review views). Supports bi-directional click-to-scroll focus back to React form cards plus 1-click **Copy Mermaid Markdown** and **Download SVG/PNG**.  
* **Multi-Record Map Explorer:** Collection-level **MapLibre GL JS** view plotting all `Place`s linked to a `Set` or query result (production sites, findspots, exhibition locations) with interactive bounding-box drawing to spatially filter records via QLever GeoSPARQL.  
* **Cross-Record Chronological Explorer:** Shared zoomable timeline across a `Set` or an artist's corpus to visually spot temporal anomalies (e.g., an artwork dated centuries after its attributed creator's death).  
* **Visual Graph Query Builder & Dynamic Smart Sets:** Faceted, multi-hop query builder compiling down to QLever SPARQL so catalogers can author queries (e.g., *"All `HumanMadeObject`s made of `oil paint` in `Amsterdam` missing a `Dimension`"*) without writing raw SPARQL, saving them as live **Dynamic Smart Sets** that open directly in the TanStack Table grid view.  
* **Global Faceted Search & Browse Workbench:** Fast faceted search landing view combining QLever full-text + `pgvector` semantic search with facets for Linked Art class, classification, material, creator, date range, map bounding box, language, IIIF availability, and draft/QA status—serving as the primary daily entry point for editors and optionally powering public discovery in the Lightweight Public Reader.  
* **Embedded SPARQL Power-User Console (YASGUI):** Embedded YASGUI SPARQL console for technical staff and digital humanists featuring Linked Art prefix/class/AAT autocomplete and `/sparql/vector SERVICE` snippets, wired directly so any SPARQL result set opens in the TanStack Table Grid, Map Explorer, Force-Directed Graph, or saves as a Dynamic Smart Set.  
* **Lightweight Public Reader Mode:** Fast, read-only public landing page served via content negotiation at `/id/{uuidv7}` for anonymous visitors and search crawlers—inspecting `Accept-Language` (with optional `?lang=` override) to set `<html lang dir>`, render localized labels and EDTF dates, expose an optional on-demand **"Translate description (Local AI)"** button backed by the disposable `ephemeral_translations` cache (clearly labeled as automated and outside the canonical Linked Art record), offering JSON-LD/Turtle download, inline IIIF viewer, Mermaid diagram toggle, immutable versioned permalinks (`/id/{uuidv7}?version=N`), Memento (`Accept-Datetime`) content negotiation for permanently reproducible scholarly citations, and citation widget—without booting the heavy React editor or Yjs WebSocket stack until an authenticated user clicks **Edit**.
