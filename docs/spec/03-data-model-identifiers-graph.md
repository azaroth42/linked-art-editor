## 3. Data Model, Identifiers & Graph Boundaries

### 3.1 PostgreSQL Storage Layout (Asymmetric Scale: 10M+ Records, 10–30 Editors)

* **`records`:** Canonical published Linked Art records stored as `JSONB` (TOAST `lz4` compression, which applies to out-of-line values) keyed by **UUIDv7** (for time-ordered B-tree locality across 10M+ rows) with **flat persistent public URIs** (e.g., `/id/{uuidv7}`, ensuring records survive reclassification while allowing class-typed routes to be injected later if desired), alongside `type`, `version`, `status` [`active`, `deleted`, `merged`], and `etag`. Indexing stays lean (B-tree indexes on UUIDv7, URI, and type—avoiding whole-document GIN indexes since QLever handles full-text and graph search).  
* **`entity_labels`:** Compact lookup table (`uri` primary key, `type`, `labels` [`JSONB` mapping BCP-47 language tags to preferred labels, e.g., `{"en": "Oil paint", "fr": "Peinture à l'huile"}`], precomputed `default_label` [`TEXT NOT NULL`] fallback, primary classification, compact `metatype_uris` and `vocab_ids` arrays, source dataset) covering both local records and locally loaded **Linked Art sidecar datasets** for sub-millisecond locale-aware transclusion reads, bidirectional UI card routing, concept-aware drag-and-drop highlighting, and SHACL membership checks without extra runtime joins.  
* **`entity_embeddings (pgvector)`:** Sibling table to `entity_labels` storing compact `halfvec` (float16) multilingual embeddings for Concepts (`Type`, `Material`, `Language`, `MeasurementUnit`, `Currency` + loaded sidecar vocabularies) and Reference Authorities (`Place`, `Person`, `Group`)—typically <= 2–3M rows—indexed with HNSW (`pgvector`, with optional `pgvectorscale` StreamingDiskANN if scaled further). Updated transactionally alongside `entity_labels` on publish and sidecar vocabulary reloads, eliminating any third data store to keep in sync while enabling native SQL pre-filtering against `entity_labels.vocab_ids` and `metatype_uris`. Embeddings encode enriched concept text (`preferred_label` + alternate labels + scope note/description + `broader` parent chain) rather than bare labels alone.  
* **`vocabularies / vocabulary_terms / slot_vocabulary_bindings`:** Lightweight metadata tables (hundreds to thousands of rows) storing named Value Set definitions (mode [`enumerated` \| `rule`], metatype URI, broader root URIs, exclusion URIs, enforcement level), curated/pinned term lists (display order, deprecated flag), with all Value Set labels, term labels, and cataloger scope notes stored as BCP-47 `LangMap` JSONB objects (with optional auto-translation review status metadata) rather than bare strings, contextual `(EntityClass, PropertyPath)` slot bindings, and a materialized membership cache refreshed automatically when sidecar datasets reload or local `Type` records change.  
* **`record_revisions`:** Immutable append-only audit log written on edits (initial bulk-loaded records remain at version 1 without duplicating payloads until edited), storing **zstd-compressed canonical N-Triples** (application-level `bytea`; PostgreSQL TOAST does not offer zstd) alongside the pinned @context version for deterministic triple diffing, where edited revisions also persist compact zstd-compressed JSON-LD snapshots (or lossless JSON patches) alongside canonical zstd N-Triples to enable arbitrary historical version browsing, `rev M` vs. `rev N` diffs, 1-click **Revert to Revision N**, and versioned/Memento permalinks, plus contributing author IDs (humans and AI agents), publishing editor ID, timestamp, edit summary, accepted validation warnings, and a shared `merge_batch_id` or `split_batch_id` for revisions created during a merge or split to enable reversible unmerges and unsplits.  
* **`crdt_drafts / crdt_updates`:** Sparse tables storing binary Yjs/`pycrdt` state only for records with active unpublished drafts (dozens to hundreds of rows, never tens of millions). Rooms hydrate lazily from `records` on open, clear on publish, and are **automatically purged after 5 days of inactivity** (reverting abandoned edits on existing records or deleting abandoned unpublished new records). Each draft room records a monotonic `draft_epoch` and `base_version` to detect stale offline client reconnects after a publish clears a room.  
* **`curation_proposals / merge_batches / split_batches`:** Relational queue for cross-record structural proposals (`merge`, `split`, `bulk_reclassify`), exempt from the 5-day CRDT draft reaper. `curation_proposals` stores `id` (UUIDv7), `proposal_type`, `source_record_id`, `target_record_id`, `status` [`pending`, `claimed`, `approved`, `rejected`, `needs_human_review`, `executed`, `superseded`], `proposed_by` (actor + model identifier), structured `evidence` (`JSONB` storing matcher signals, confidence, and rationale), `field_resolution_plan` (`JSONB`), `reviewed_by`, `review_rationale`, `claim_expires_at` lease timestamp, and a `block_resubmission` negative-cache flag preventing cheap sweep agents from endlessly re-proposing rejected "Do Not Merge" pairs. `merge_batches` stores pre-merge manifests (exact source record state plus rewritten referencing UUIDs and JSON paths) linked via `merge_batch_id` for 1-click Unmerge. `split_batches` stores pre-split manifests (original conflated record state, newly minted UUIDv7 record ID, and selectively reassigned inbound referencing UUIDs and JSON paths) linked via `split_batch_id` for reversible splits.  
* **`comment_threads / comments`:** Anchored discussion threads (anchor = record URI or internal sub-node IRI, `open`/`resolved` state) and their comments with `@user` / `@agent` mentions, retained across publishes since anchors are stable.  
* **`agent_jobs`:** Server-owned asynchronous job table for long-running agent operations (batch translation, IIIF transcription, set enrichment) storing `status`, progress counters, per-item results, cancellation flag, and the invoking actor; exposed to MCP clients as `linkedart://job/{id}` progress resources.  
* **`watchlists / notifications / saved_smart_sets / qa_findings / curation_campaigns / agent_audit_log / agent_quotas / ephemeral_translations`:** Lightweight relational tables supporting Wikidata-style watchlists (records, `Set`s, and Value Sets), @mention/escalation notifications, saved Visual Query Builder Smart Sets, scheduled cross-record QA and link-rot worklists, `curation_campaigns` (tracking Queue Focus Mode progress, skipped records, and optional cataloger assignments over `Set`s, Dynamic Smart Sets, and `qa_findings`), per-agent MCP audit logs, rate-limit quotas, circuit-breaker flags, and `ephemeral_translations` (disposable cache keyed by `(record_id, version, target_lang, model_id)` for optional on-demand Public Reader translations, automatically invalidated on new revisions and never touching `records` or QLever). Note that `notifications` and `qa_findings` store structured typed event payloads rather than frozen English prose so clients localize them dynamically.  
* **`llm_provider_configs / agent_chat_sessions / agent_chat_messages`:** Lightweight tables storing envelope-encrypted LLM provider configurations and API keys (`llm_provider_configs`, encrypted at rest via an instance master key from env/KMS, supporting institutional admin-configured keys and optional admin-togglable per-user BYOK keys for Gemini, Claude, OpenAI, and institutional cloud endpoints alongside local models—never exposed to browsers or logs) plus persistent chat threads (`agent_chat_sessions`, `agent_chat_messages`, optionally linked to a `record_id` or `set_id` with configurable retention).  
* **`backup_jobs / usage_metrics_daily / sidecar_datasets / system_settings / webhooks / webhook_deliveries / admin_audit_log`:** Lightweight operational tables supporting automated/on-demand backup run metadata and restore-verification checksums (`backup_jobs`), rolled-up per-user, per-class, and per-function usage analytics without storing sensitive query PII (`usage_metrics_daily`), versioned manifests for locally loaded Linked Art sidecar datasets (`sidecar_datasets`), versioned operational thresholds and SSRF egress rules (`system_settings`), HMAC-signed outbound webhook subscriptions and delivery retry logs dispatched from `outbox_events` (`webhooks` / `webhook_deliveries`), and an immutable, SIEM-exportable administrative security and configuration audit log (`admin_audit_log`).  
* **`outbox_events`:** Written in the same DB transaction as any incremental publish (including bundled dependent stubs), merge, or delete to guarantee at-least-once delivery to QLever.

### 3.2 Normalized Stubs & Read-Time Transclusion

Linked Art documents routinely embed references to external entities (artists, places, concepts, collections) as stubs containing `id`, `type`, and `_label`.

* **Local Sidecar Datasets for External Authorities (No Live Remote Queries):** External vocabularies and reference datasets (Getty AAT/ULAN/TGN, Wikidata, GeoNames, etc.) are loaded locally as Linked Art into sidecar datasets. The editor never performs live external web requests or remote SPARQL queries during CRDT editing sessions.  
* **Uniform Write-Time Normalization:** Both local and external entity references follow the exact same rule: before persisting to PostgreSQL, references are stripped down to canonical stubs (`{"id": "...", "type": "..."}`), discarding mutable labels. The one exception is a reference whose target has no `entity_labels` row (neither a local record nor a loaded sidecar entity, e.g., a pasted external URI): its incoming `_label` is retained as a fallback and the reference is flagged as an *unresolved reference* `qa_findings` item, since stripping it would lose the only label available. When expanding a record to RDF for QLever, non-owned stub attributes (`_label`, `type`) on referenced entities are similarly stripped so only the linking triple is emitted, enforcing strict subject ownership in the flat graph.  
* **Read-Time Transclusion:** On API read, export, or UI hydration, current `_label` (and optionally primary classification) values are dynamically resolved from local records and sidecar datasets via a single batched index-only lookup against the compact `entity_labels` table. Transclusion takes the caller's ordered `locale_chain` (from `Accept-Language`) to resolve `_label` in the user's preferred UI language from `entity_labels.labels`, falling back cleanly to `default_label`. Renaming an artist or refreshing a sidecar vocabulary immediately propagates everywhere without cascading record updates or triplestore deletion anomalies.

### 3.3 Flat Graph Model, Revision-Diff Syncing & Skolemized Nested Nodes

* **Flat Default Graph + Local Sidecar Graphs:** Maintaining millions of per-record named graphs introduces high SPARQL query complexity, dictionary bloat, and cross-record join overhead. All local published Linked Art records are indexed into a single flat default graph in QLever. External authorities loaded as Linked Art sidecar datasets live in a small, fixed set of coarse-grained sidecar graphs (e.g., `urn:graph:sidecar:<dataset>`), keeping total graph count minimal and enabling independent bulk refreshes.  
* **Revision-Diff Syncing (DELETE DATA / INSERT DATA):** On publish, the sync worker computes the exact triple set difference between `rev N-1` and `rev N` (`T_delete = triples(rev N-1) - triples(rev N)` and `T_insert = triples(rev N) - triples(rev N-1)`) and issues a single idempotent SPARQL 1.1 `DELETE DATA` / `INSERT DATA` update. This minimizes delta-triple churn in QLever's edit sidecar—editing a single title retracts 1 triple and inserts 1 triple rather than churning the entire record.  
* **Strict Subject Ownership:** A Linked Art record may only emit triples to QLever whose subject is owned by that record (its root IRI and internal record-scoped sub-node IRIs). References to other local records or sidecar external entities emit only the linking triple—never the target's `rdf:type` or `rdfs:label`—eliminating deletion anomalies.  
* **Internal Skolemized Slash Paths (Never Exposed Externally):** Because SPARQL `DELETE DATA` cannot delete blank nodes across requests, nested structures (`Name`, `Identifier`, `Dimension`, `Production`, `TimeSpan`, `AttributeAssignment`) receive stable, internal record-scoped **slash-path IRIs** (`<record_uri>/node/<uuid>`) inside PostgreSQL, CRDT state, and QLever. These internal sub-node IRIs enable deterministic triple diffing, field-anchored comments, and keyed CRDT merging, but are **strictly internal—never shown in the UI and always stripped back to anonymous nested objects / blank nodes in public JSON-LD and RDF exports**. (They necessarily appear in SPARQL results from QLever; `/id/{uuidv7}/node/{id}` therefore 303-redirects to the parent record rather than 404ing.)  
* **Locked zstd N-Triples & Blue/Green Offline Rebuilds:** Edited revisions persist **zstd-compressed canonical N-Triples** so `triples(rev N-1)` is guaranteed exact without re-expansion drift. Initial multi-million-record migrations bootstrap via PostgreSQL `COPY` and offline QLever `IndexBuilderMain`. QLever runs with `--persist-updates` so delta triples survive server restarts, and the sync worker persists a `qlever_index_watermark` (the last `outbox_events` id applied to the live index) so replay after any crash, restore, or rebuild is deterministic. Ongoing maintenance uses a **blue/green rebuild**: when the delta-triple count exceeds a **configurable threshold** (or on admin demand), a new index is built with `IndexBuilderMain` from a PostgreSQL snapshot taken at a recorded watermark in a second index directory, outbox events past that watermark are replayed into the new index, and traffic is switched atomically—the Public Reader, autocomplete, and public SPARQL endpoint stay online throughout, and the previous index is retained for rollback. Rebuilds never depend on "no editors logged in", since public traffic is continuous.  
* **First Edit of Bulk-Loaded Records:** Bulk-loaded records carry no stored N-Triples, so `triples(rev N-1)` for their first edit is re-expanded from the stored JSON-LD. Each bulk build records the pinned `@context` version and expander version it used; if the current versions differ, the sync worker issues `DELETE WHERE { ?s ?p ?o }` over the record's owned subjects (root IRI plus its `/node/` IRIs) instead of a computed diff, then `INSERT DATA` for the new triple set. A sampled PostgreSQL-vs-QLever consistency audit in the scheduled QA sweeper detects orphaned or missing triples.

### 3.4 Referential Integrity, Merges & Tombstones

* **Delete Protection:** Before deleting a record, the API queries QLever for inbound references. If referenced, hard deletion is blocked; users must either unlink references or merge the record.  
* **Tombstones:** Deleted records remain in Postgres with `status = 'deleted'`, serving HTTP `410 Gone` to public dereferencers and retracting their owned triples from QLever via DELETE DATA.  
* **Entity Merge Workflow:** Merging Record A into Record B rewrites all inbound references in Postgres (enqueuing affected records in the outbox), appends A's URI to B's `equivalent` array, and sets A to `status = 'merged'` (serving HTTP `301 Moved Permanently` to B).  
* **Safe Merge Execution & 1-Click Unmerge:** Before executing any merge (human or agent-approved), FastAPI checks whether Record A or Record B has an active `crdt_draft` or live WebSocket session and defers execution if actively being edited, avoiding mid-session invalidation. Both rows are locked via `SELECT ... FOR UPDATE` in deterministic UUIDv7 order (preventing deadlocks and double-merges) after verifying both remain `status = 'active'`. Every `record_revision` generated during a merge shares a `merge_batch_id` pointing to a pre-merge manifest in `merge_batches`, allowing human Editors to perform a clean **1-click Unmerge** if an automated or manual over-merge occurs.  
* **Entity Split Workflow (`split_batch_id`):** Guided dual-pane Split Workbench for executing `split` proposals from `curation_proposals` (or manually separating conflated entities such as homonymous artists, father/son workshops, or combined buildings/institutions). Defers execution if the source record has an active CRDT session, locks affected rows deterministically, mints a new UUIDv7 record, partitions statements and `equivalent` links, selectively reassigns inbound QLever backlinks atomically in PostgreSQL (enqueuing updated referencers in `outbox_events`), and links all generated `record_revisions` via `split_batch_id` pointing to a pre-split manifest in `split_batches` for 1-click rollback.  
* **Safe Record Reclassification Wizard:** Leveraging flat `/id/{uuidv7}` URIs so records survive class changes (e.g., `Person` <-> `Group`, `HumanMadeObject` <-> `Set`), checks QLever inbound predicate compatibility first (blocking or flagging invalid backlinks such as `took_place_at` if reclassifying `Place` -> `Group`), remaps compatible fields onto the target Declarative UI Profile, and surfaces incompatible subgraphs for explicit resolution prior to publishing.
