## 11. Proposed Technology Stack

| Layer | Recommended Choice | Rationale |
| :---- | :---- | :---- |
| **Backend API** | Python 3.12+ / **FastAPI** + **pycrdt** / **pycrdt-websocket** + **MCP Python SDK v2** | Native async I/O for REST, QLever queries, Rust-backed Yjs-compatible WebSocket CRDT rooms, stateless /mcp server, in-process Agent Chat Orchestrator (MCP client loopback), unified Multi-Provider LLM Adapter Layer (local llama.cpp/vLLM/Ollama + cloud Gemini/Claude/OpenAI via encrypted llm_provider_configs with optional per-user BYOK), warm local multilingual embedding worker (ONNX Runtime / llama.cpp), OpenAI-compatible local LLM translation client with two-speed model routing, semaphore prioritization, and graph-grounded glossary injection, /sparql/vector SPARQL SERVICE wrapper, on-demand reconciler client, /health/live, /health/ready, Prometheus/OpenMetrics /metrics endpoints, SSRF egress filtering for URL introspection and link-rot checks, Memento (Accept-Datetime / ?version=N) negotiation, draft_epoch offline rebase guard, and HMAC-signed outbound webhook dispatching from outbox_events; strong Pydantic typing. |
| **Database** | **PostgreSQL 16+ + pgvector** (`asyncpg` / SQLAlchemy) | Handles tens of millions of LZ4-compressed JSONB records keyed by UUIDv7, zstd canonical N-Triples and lossless zstd JSON-LD snapshots/patches on edited revisions, unified local+sidecar entity_labels transclusion lookups with entity_labels.labels JSONB + default_label, metatype_uris and vocab_ids arrays, entity_embeddings (pgvector halfvec HNSW, optional pgvectorscale) synced transactionally with entity_labels for SQL-filtered Value Set semantic search without introducing a third store, vocabularies (with LangMap JSONB) and slot_vocabulary_bindings metadata tables, curation_proposals (with negative-cache blocking), merge_batches (reversible 1-click Unmerge), split_batches (reversible 1-click Unsplit), watchlists, saved_smart_sets, qa_findings, curation_campaigns, agent_audit_log, agent_quotas, llm_provider_configs (envelope-encrypted provider/BYOK keys), agent_chat_sessions/agent_chat_messages, ephemeral_translations disposable cache table, webhooks/webhook_deliveries, pgBackRest/Barman PITR backups (automated + on-demand), operational tables (backup_jobs, usage_metrics_daily, sidecar_datasets, system_settings, admin_audit_log), LISTEN/NOTIFY outbox triggers, and sparse 5-day TTL CRDT draft storage with draft_epoch/base_version. |
| **Triplestore** | **QLever** | Proven at multi-billion-triple scale with low memory footprint; supports fast full-text + SPARQL queries, SPARQL 1.1 Update (DELETE DATA / INSERT DATA), and coarse-grained graphs. Invokes PostgreSQL pgvector directly via FastAPI's /sparql/vector SPARQL SERVICE wrapper, keeping the stack at two stores while preserving a clean migration seam if native QLever vector indexing matures. |
| **RDF / Validation** | `rdflib` / `pyoxigraph` + `pyshacl` + `jsonschema` | `pyoxigraph` (Rust-backed) offers high-throughput JSON-LD/N-Triples serialization and set-diffing for the sync worker; `pyshacl` handles SHACL shapes. |
| **Frontend** | **TypeScript + React 19** + **Yjs** + TanStack Query | Best ecosystem fit for cultural heritage authoring: embeddable IIIF viewing (Canvas Panel web component, Clover IIIF for A/V), mature Yjs bindings (with UndoManager), MapLibre GL JS + Terra Draw spatial authoring, WebGL force-directed graph visualization (Sigma.js + Graphology / react-force-graph-2d), client-side Mermaid.js record diagramming, Visual Query Builder, Global Faceted Search Workbench, embedded YASGUI SPARQL console, Revision History Browser, Entity Split & Reclassification Wizards, Curation Queue Focus Mode, Pre-Creation Duplicate Guard, Offline Rebase Modal, Lightweight Public Reader mode, Embedded Agent Chat drawer (SSE streaming, context chips, turn-scoped Yjs undo), WCAG 2.2 Level AA compliance (axe-core + Playwright CI checks, keyboard D&D/canvas equivalents, prefers-reduced-motion), Administration Control Plane UI (health/outbox monitoring, on-demand backups, usage analytics, user/token directory, sidecar/policy consoles), ontology-aware drag-and-drop, TanStack Table grid view for Sets, React Flow mini-graph, react-i18next + i18next-icu (route-scoped namespaces, browser Intl APIs, CSS Logical Properties for RTL readiness, and dev pseudo locale), and schema-driven nested forms. |
| **Real-Time / Cache** | **PostgreSQL** (in-process memory + DB cache; Redis optional) | At 10–30 concurrent users, a single CRDT WebSocket worker holds active rooms in memory and PostgreSQL caches external authority lookups (Getty/Wikidata)—no Redis required for v1. |
