## 6. Schema-Driven UI & Ergonomics (continued)

### 6.7 Internationalization (i18n/l10n) & Local LLM Translation

* **Four-Layer i18n Architecture (Shipping `en`-Only on Day 1 Without Retrofit):**  
  * *Layer 1 — Static UI Chrome & RTL Foundations:* Uses **`react-i18next` + `i18next-icu`** (ICU MessageFormat supporting complex plural/gender rules) with route-scoped JSON namespaces (`common`, `public_reader`, `editor`, `graph`, `vocab_admin`, `errors`) so the Lightweight Public Reader stays lean. All dates, numbers, 5-day TTL countdowns, backlink counts, and lists format through browser `Intl` APIs. Components strictly use **CSS Logical Properties** (`margin-inline-start`, `padding-inline-end`, Tailwind `ms-*`/`me-*`/`start-*`/`end-*`) for zero-cost RTL mirroring while keeping per-field Linked Art data `dir` independent of UI direction.  
  * *Layer 2 — Declarative Config LangMaps:* UI Profiles and Vocabulary Registry entries store human-readable labels and scope notes as BCP-47 `LangMap`s resolved via shared RFC 4647 fallback (`user profile pref -> localStorage -> Accept-Language -> DEFAULT_LOCALE=en`).  
  * *Layer 3 — Structured Backend Diagnostics & Events:* FastAPI validation errors, Semantic Diffs, `notifications`, and `qa_findings` persist and emit typed codes + parameters rather than pre-rendered English prose.  
  * *Layer 4 — Multilingual Data Transclusion & CI Guardrails:* Locale-aware transclusion reads from `entity_labels.labels` JSONB + `default_label` (and multilingual `entity_embeddings` automatically supports cross-lingual semantic autocomplete). CI enforces `eslint-plugin-i18next` (`no-literal-string`) and YAML `LangMap` schema checks from commit #1, paired with a dev-only `pseudo` locale (\~35% text expansion) and 1-click RTL toggle to catch unwrapped strings and layout overflow before any real translation exists.  
* **Shared Local LLM Translation Layer:** Reuses the local-inference pattern alongside FastAPI's warm embedding worker via a configurable OpenAI-compatible `/v1/chat/completions` client (`llama.cpp` server, `vLLM`, or `Ollama`—zero cloud APIs). Supports **two-speed model routing** (fast 4B–9B quantized interactive tier for inline editor and on-demand Public Reader clicks; 14B–32B high-quality batch tier for CI catalog drafting, Vocabulary Manager localization, and MCP batch enrichment), a bounded async semaphore queue prioritizing interactive human requests ahead of background MCP jobs, and **graph-grounded glossary injection** pulling authoritative multilingual terms from `entity_labels` (local + AAT/Wikidata sidecars) and the Vocabulary Registry into the prompt.  
* **Track A — UI & Config Localization (Offline & Admin-Time):** A CLI/CI diff pipeline (`la-i18n translate`) hashes canonical `en` ICU keys and drafts only new/changed strings via the local LLM, gated by an automated **ICU AST validator** (verifying placeholders, target-language plural categories, tags, and length budgets, with error-feedback retries) and a provenance lockfile (`machine_draft` vs. `human_reviewed`, never overwriting confirmed human edits). In the Vocabulary Manager Admin UI, localizing terms resolves authoritative sidecar dataset labels (AAT, Wikidata, ISO 639) first before offering a 1-click **"Translate Missing Labels & Scope Notes"** local LLM action (badged as auto-translated until confirmed).  
* **Track B — Entered Linked Art Data Translation (Additive, Provenance-Tracked & Safeguarded):**  
  * *Persisted Authoring (Editor & MCP Batch):* Hard allowlist restricts data translation strictly to `Name.content` and `LinguisticObject.content` (never `Identifier`s, ISO `TimeSpan` bounds, `Place.defined_by` WKT strings, URIs, or diplomatic transcriptions). Never overwrites source text: appends a sibling `Name` (`classified_as aat:300417194`*Translated Title*) or `LinguisticObject` in the live `pycrdt` draft room with mandatory Linked Art `AttributeAssignment` (`assigned_by`) recording the translation activity, model ID/version, timestamp, and `source_content_hash`. Unreviewed entries display a *"Machine-translated"* badge until human Editor publication, at which point `entity_labels` and `entity_embeddings` update transactionally. Subsequent edits to the source node trigger *"Source text changed since translation"* staleness badges and `qa_findings` worklist items with 1-click **Re-translate**.  
  * *Ephemeral Public Reader Translation:* Optional on-demand local LLM translation for anonymous visitors browsing in an unauthored locale, cached in disposable `ephemeral_translations` (invalidated automatically on new revisions), clearly labeled as non-canonical, and never written to `records` or QLever.
