## 14. Locked Architectural Decisions & Next Design Artifacts

| Decision Area | Locked Choice |
| :---- | :---- |
| **Graph Model** | Flat default graph in QLever (+ coarse-grained local sidecar graphs); revision-diff DELETE/INSERT syncing; internal slash-path IRIs for nested nodes (stripped on export). |
| **Collaboration Model** | Full real-time CRDT co-editing (Yjs + pycrdt-websocket, behind a narrow room-manager interface) with keyed Y.Map graph modeling and fractional-index `_order` for lossless array order; single `crdt-ws` process with validate/publish routed to it over internal RPC; monotonic draft_epoch/base_version with a v1 Rebase Offline Changes Modal (per-change Apply/Discard list) preventing blind replay of stale offline Yjs edits after a publish. |
| **Draft & Review Workflow** | One shared live CRDT draft per actively edited record; collaborators co-edit freely, Editors only can publish. |
| **Data Visibility & Security** | Fully open LOUD once published (no private published records or field redaction); write-only governance and record protection. |
| **Tenancy** | Single-tenant per installation (deploy separate instances for separate platforms). |
| **Scale Profile** | Tens of millions of records (billions of triples), 10–30 concurrent editors; lean Postgres indexing, sparse CRDT tables, no Redis required. |
| **Frontend Stack** | TypeScript + React 19 (chosen for embeddable IIIF viewing via Canvas Panel, mature Yjs tooling, and complex form support). |
| **Identifiers & Sub-Nodes** | UUIDv7 keys; flat public URIs (/id/{uuidv7}); internal slash-path skolemized sub-nodes never exposed in UI or public exports. |
| **External Authorities** | Locally loaded Linked Art sidecar datasets + QLever sidecar graphs (no live external web/SPARQL calls during CRDT editing); uniform stub-and-hydrate model. |
| **Vocabulary Management** | Two-tier Value Sets (curated ETag-cached lists + rule/metatype/hierarchy-backed QLever sets) bound to (EntityClass, PropertyPath) slots; single source of truth across UI cards, SHACL enforcement, concept-aware D&D, and MCP resources, with YAML/JSON export and deprecation migration. |
| **Draft Dependencies & Expiry** | Bundled transactional publish for newly minted dependent stubs; 5-day inactivity TTL automatically purges abandoned CRDT drafts. |
| **Reconciliation** | On-demand HTTP callout only to a dedicated `lae-reconcile` process built on the LUX pipeline's LMDB reconciler and index code (network off, candidates returned with evidence)—never automatic/background. |
| **Triple Diffing & QLever Rebuilds** | zstd-compressed canonical N-Triples stored on edited revisions; `DELETE WHERE` over owned subjects for first edits of bulk-loaded records when context/expander versions have drifted; QLever `--persist-updates` plus a `qlever_index_watermark`; blue/green IndexBuilderMain rebuilds (snapshot at watermark, replay, atomic swap) triggered by the delta-triple threshold or on demand, never by editor idleness. |
| **Workbench UI Affordances** | Ontology-aware D&D, MapLibre+Terra Draw, record cloning/templates, Linked-Entity Composite Creation Flows, Inverse-Link Authoring in Backlinks, Curation Campaign Queue Focus Mode, Pre-Creation Duplicate Guard, Revision History Time-Travel & 1-Click Revert, Entity Split Workbench (split_batch_id), Safe Record Reclassification Wizard, dual-pane editing/merge view, backlinks + mini-graph, provenance timeline, spreadsheet grid view for Sets, Cmd+K, user-scoped undo, and Smart Paste. |
| **AI Agent Collaboration** | Stateless Streamable HTTP MCP server (/mcp, SDK v2) inside FastAPI; Tier 1 discovery/draft agents co-edit live pycrdt rooms (edit_draft), claim QA worklists, and submit merge proposals; Tier 2 frontier arbiter agents review proposals under policy guardrails; long-running operations use a server-owned `agent_jobs` job model (not the MCP Tasks extension). |
| **Multi-Agent Merge & Proposal Queue** | Persistent curation_proposals table (exempt from 5-day draft TTL) with lease claiming and a "Do Not Merge" negative cache; Tier 2 agents auto-execute low-blast-radius merges (unprotected, below backlink threshold or exact external ID match, non-contradictory), reject false positives, or escalate (needs_human_review) to human Editors in the Visual Merge Workbench; active CRDT room deferral, UUIDv7-ordered locking, and merge_batch_id enable 1-click Unmerge. |
| **Graph Visualization & Macro-Explorers** | Global Faceted Search & Browse Workbench; Embedded SPARQL Power-User Console (YASGUI) wired directly into Grid, Map, Graph, and Dynamic Smart Sets; WebGL force-directed multi-record explorer (Sigma.js/Graphology or react-force-graph-2d) with supernode protection, drag-to-form, cluster-to-merge, shortest path, and live CRDT draft overlay; pure-function client-side Mermaid record diagramming (Conceptual, Full CRM, Visual Diff modes; click-to-scroll; no exposed slash IRIs); multi-record MapLibre explorer; cross-record timeline; Visual Query Builder saving Dynamic Smart Sets. |
| **Editorial Operations, QA & Public Reader** | Active Drafts & Review Inbox with 5-day TTL expiry triage and 1-click Extend TTL; Watchlists, @mentions (open/resolved threads), and Notification Inbox; scheduled QLever cross-record QA & link-rot sweeps (qa_findings); lightweight read-only Public Reader at /id/{uuidv7} deferring Yjs/editor boot until Edit. |
| **Agent Observability & Safety Controls** | Agent Operations Console with per-agent rate limits, daily auto-merge caps, live tool-call audit log, per-model over-merge/unmerge rate tracking, and a 1-click "Pause All Agents / Pause Auto-Merge" circuit breaker. |
| **Semantic Vector Search & Autocomplete** | PostgreSQL `pgvector` (`halfvec` HNSW, optional `pgvectorscale`) in `entity_embeddings` covering Concepts & Reference Authorities (<= 2–3M rows, transactional with `entity_labels`—no third sync store); enriched concept text embedded by a warm local multilingual worker (<20–40ms); native SQL `vocab_ids`/`metatype_uris` filtering; hybrid QLever lexical + `pgvector` RRF blending on `rule`-backed Value Sets and entity slots; exposed to QLever via FastAPI's `/sparql/vector` SPARQL `SERVICE` wrapper. |
| **Interoperability & Batch Staging** | ActivityStreams 2.0 /activity/stream aligned with the IIIF Change Discovery API; Outbound Signed Webhooks dispatched from outbox_events; Versioned Permalinks & Memento (Accept-Datetime) negotiation; Interactive Batch Staging Wizard (dry-run CSV/JSON-LD mapping, SHACL preview, duplicate check, reversible batch ID); scheduled and on-demand Full Bulk LOUD Exports. |
| **i18n/l10n & Local LLM Translation** | Four-layer i18n built from day 1 (en-only initial ship): react-i18next + i18next-icu with route-scoped namespaces, Intl APIs, CSS Logical Properties (RTL-ready), CI no-literal-string lint gate, and dev pseudo locale; BCP-47 LangMaps in UI Profiles/Vocabs; structured backend diagnostic codes; entity_labels.labels JSONB + default_label for locale-aware transclusion. OpenAI-compatible local LLM (llama.cpp/vLLM/Ollama, two-speed 4B–9B interactive + 14B–32B batch) with graph-grounded glossary injection powers offline ICU/config translation (with ICU AST validation & human_reviewed lockfile), additive pycrdt Linked Art data translation (Name/LinguisticObject allowlist, mandatory AttributeAssignment + source_content_hash staleness tracking, MCP translate_record_fields), and optional ephemeral Public Reader translations (ephemeral_translations). |
| **Embedded Agent Chat & Multi-Provider LLMs** | Collapsible React Agent Chat drawer backed by an in-process FastAPI MCP client orchestrator (zero duplicated tools; inherits `pycrdt` routing, audit logs, quotas, and circuit breaker); removable workspace context chips and `@agent` thread handoff; unified LLM adapter supporting local models (`llama.cpp`/`vLLM`/`Ollama`) plus cloud frontier APIs (Gemini, Claude, OpenAI, Vertex/Bedrock/Azure); envelope-encrypted institutional admin keys in `llm_provider_configs` with optional admin-togglable per-user BYOK, `local_only` vs. `allow_cloud` switch, `user_perms ∩ agent_tier_perms` permission intersection, dual attribution, in-chat confirmation cards, and 1-click turn-scoped Yjs undo. |
| **Accessibility (WCAG 2.2 Level AA)** | WCAG 2.2 Level AA across Lightweight Public Reader and editor/admin workspaces: single-pointer/keyboard equivalents for all drag-and-drop (SC 2.5.7), >=24×24 CSS px targets (SC 2.5.8), non-obscured visible focus (SC 2.4.11/2.4.13), accessible parity for Map/Graph/Mermaid/IIIF canvases (`prefers-reduced-motion`, Backlinks list, WKT forms, SVG metadata), disciplined `aria-live` updates (no CRDT keystroke noise), and automated `axe-core` + Playwright CI gates. |
| **Administration Control Plane & Operations** | Dedicated `System Admin` / `Ops` control plane (separate from editorial `publish` rights): automated PostgreSQL PITR (`pgBackRest`/`Barman`) + 1-click on-demand backups, restore verification, and cold QLever snapshots; `/health/live`, `/health/ready`, Prometheus `/metrics`, live process/outbox dead-letter monitoring, and daemon controls; rolled-up per-user/per-class/per-function usage analytics (CSV/JSON export); OIDC IdP group mapping, immediate session revocation, PAT/service-account lifecycle, and effective-permission debugging; sidecar dataset cascade manager, Read-Only Maintenance Mode + editor broadcast banners, central policy & SSRF egress allowlist/denylist, zero-downtime embedding migrations, protected/batch/merge rollback console, and SIEM-exportable `admin_audit_log`. |

### Next Design Artifacts

1. **PostgreSQL DDL & Transclusion Schema:** Concrete table definitions, LZ4 compression settings, `entity_labels` triggers/updates (including `entity_labels.labels` JSONB + `default_label`, `metatype_uris` and `vocab_ids` arrays), `entity_embeddings` (`pgvector halfvec` HNSW index definitions and transactional sync with `entity_labels`), `vocabularies` (with `LangMap` JSONB columns)/`vocabulary_terms`/`slot_vocabulary_bindings`, `curation_proposals`/`merge_batches`/`split_batches`, `watchlists`, `saved_smart_sets`, `qa_findings`, `curation_campaigns`, `agent_audit_log`/`agent_quotas`, `llm_provider_configs` (envelope-encrypted provider/BYOK keys), `agent_chat_sessions`/`agent_chat_messages`, `ephemeral_translations`, `webhooks`/`webhook_deliveries`, `backup_jobs`, `usage_metrics_daily`, `sidecar_datasets`, `system_settings`, `admin_audit_log`, sparse CRDT persistence tables with `draft_epoch`/`base_version`, and lossless zstd JSON-LD snapshots/patches on `record_revisions`.  
2. **Yjs / `pycrdt` to Linked Art Projection Spec:** Exact rules mapping Linked Art JSON-LD structures to keyed Y.Maps, Y.Text leaves, internal slash-path sub-node IRIs, fractional-index `_order` assignment and sorting, deterministic canonical export, stripping sub-node IRIs on public serialization, and `draft_epoch` stale-base detection with offline rebase reconciliation.  
3. **Declarative UI Profile & Vocabulary Registry Specification:** YAML/JSON profile formats for flattening HumanMadeObject, Person, Place, and Concept records, defining BCP-47 `LangMap` schemas and RFC 4647 fallback resolution for curated/rule-backed Value Sets, and binding slots with lossless round-tripping.  
4. **Bulk Bootstrap & Incremental Sync Worker Design:** Offline COPY + QLever IndexBuilderMain pipeline alongside the LISTEN/NOTIFY revision-diff sync worker and HMAC-signed outbound webhook dispatching from `outbox_events`.  
5. **MCP Server, Proposal Queue & Reconciliation Service Contract:** Tool/Resource schemas for /mcp (SDK v2) across Tier 1 and Tier 2 agents (including `translate_record_fields` via the `agent_jobs` job model and the local LLM translation + glossary injection service contract), Embedded Agent Chat Orchestrator (in-process MCP client loopback), Multi-Provider LLM & BYOK key-vault contract, permission intersection rules, SSE streaming/confirmation schema, blast-radius guardrail policy config, Yjs Awareness agent presence conventions, Agent Operations Console quotas/circuit-breaker config, `qa_findings` worklist tools, FastAPI `/sparql/vector` SPARQL `SERVICE` & hybrid RRF autocomplete contract, and the HTTP request/response adapter for the on-demand reconciliation pipeline.  
6. **Operations, Backup & Administration Control Plane Spec:** API contracts and runbooks for `pgBackRest`/`Barman` PITR backups (automated + on-demand + restore verification), Prometheus/OpenMetrics telemetry & health probes, outbox dead-letter recovery, usage analytics rollups, OIDC role/token management, sidecar refresh orchestration, SSRF egress policies, zero-downtime embedding model migrations, `split_batches` rollback, and outbound webhook subscription/delivery monitoring.

### Open Questions & Spikes

1. **`/sparql/vector` SPARQL `SERVICE` wrapper vs. application-layer fusion:** Undecided, but informed by an existing implementation: the LUX middle tier's `sparql_service` package is a tested SPARQL `SERVICE` endpoint that QLever federates to, with a `vec:` predicate vocabulary, a parser for QLever's pushed-down `VALUES` block, graph-first and vector-first modes, and documented pitfalls (no SERVICE timeout in QLever, the `service-max-value-rows` silent cutoff, unshared duplicate SERVICE calls). The leading option is to port that contract to `pgvector`; the alternative remains RRF fusion in FastAPI with `pgvector` hits injected as `VALUES`, retaining SERVICE only as a YASGUI convenience. Decide in Phase 3 after Spike S1.  
2. **QLever text-index freshness for autocomplete:** Autocomplete and graph-aware search stay in QLever. Spike: confirm that `ql:contains-word` prefix search covers literals inserted via SPARQL Update (word-lookup triples for updated literals landed upstream recently) so newly published stubs autocomplete before the next rebuild; otherwise overlay recently published entities from `entity_labels` until the blue/green rebuild catches up.  
3. **`pycrdt-websocket` under load:** Validate awareness fan-out, room eviction, and reconnect behaviour with 30 simulated editors before locking; fallback is a Yjs-wire-compatible sidecar behind the same room-manager interface.  
4. **SHACL latency budget:** Measure `pyshacl` (or a compiled evaluator) against the project-authored shapes per class to set the per-record budget assumed by the Batch Staging Wizard and agent self-correction loops.
