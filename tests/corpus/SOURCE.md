## Institutional records (`institutional/`)

Hand-collected on 2026-11-22; not regenerated by any script. Each file is the exact HTTP response
body of an unauthenticated `GET` (generic User-Agent, no credentials) to the URL in the table; the
`id` of every record equals its source URL.

**Why these publishers and not `lux.collections.yale.edu`:** the guide asks for LUX public records,
but every request to `https://lux.collections.yale.edu/data/...` and `/api/search/...` returns
`202` with an empty body and `x-amzn-waf-action: challenge` (an AWS WAF JavaScript challenge), so a
plain HTTP client cannot fetch them. The adjacent repositories' test fixtures contain no real
records (only synthetic ones written in code). The records below come instead from the public
Linked Art feeds that LUX itself harvests: the Yale Center for British Art (YCBA), the Yale
University Art Gallery (YUAG) and Yale University Library (YUL). Record URLs were discovered from
the publishers' change feeds (`https://ycba-lux.s3.amazonaws.com/activity_stream/page35.json`,
`https://media.art.yale.edu/discovery/lux/changes-001.json`) and from references between records;
the two YUL URLs appear in `lux/data-pipeline` tests. All use the pinned context
`https://linked.art/ns/v1/linked-art.json`. The records do not state a metadata licence (the only
CC0 statements are on images in the three `VisualItem` records); see `docs/questions.md`, Step 0.4.

Coverage: 5 HumanMadeObject, 5 Person, 3 Group, 2 Place, 3 Type, 4 VisualItem, 3 LinguisticObject,
4 Set, 4 Activity (33 records). The SHA-256 column is the first 16 hex digits of the hash of the
file as stored.
